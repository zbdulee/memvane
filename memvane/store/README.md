# View와 blob store

- `laya_checkout_view.py` — caller가 보관하는 저장소·워크트리 등록 JSON과 Git checkout capture API. 경로·dev/ino, ref·HEAD·index·operation을 재검증하고 view identity를 계산한다. view store가 binding·capture를 검증할 때 쓴다. recall pin과 sync 게시가 이 경로로 checkout을 관측한다. API와 증명 범위는 `docs/development-checkout-capture.md` 참고.
- `laya_blob_store.py` / `laya_blob_schema.py` / `laya_blob_values.py` — schema3 view store의 내용 층인 private Git-blob 형식의 wiki admission·불변 body/recipe/profile/set·metadata provenance. 원문 body API는 없다. `put_fingerprint`·`put_attestation`에 넘기는 지문·receipt는 호출자의 증거 주장이다. schema3 sync 게시는 `ingest_attested_card`를 쓴다: 저장소가 카드 frontmatter를 recall의 신뢰 규칙(`legacy_card_evidence`)으로 직접 판정해 통과한 카드에만 `legacy_unbound` 지문의 `legacy_verified` attestation을 붙이고, 현재 HEAD를 과거 compile commit으로 쓰지 않는다. 구조 제약과 의미 검증, API·상한은 `docs/development-blob-candidate.md` 참고.
- `laya_blob_lease.py` / `laya_blob_fill.py` — view store의 private content flock과 불변 complete set 채우기. schema3 sync의 vector fill이 이 경로로 content set을 재사용한다(두 view가 공유하는 content는 한 번만 임베딩). 캐시는 읽기 전용이고 callback은 SQLite transaction 밖에서 실행한다. claim은 협력적 발급 객체·보유 FD 계약이며 운영 owner 권한이나 임의 동일 UID FD 조작에 대한 보안 경계가 아니다. API는 `docs/development-blob-candidate.md` 참고.
- `laya_view_fill.py` / `laya_fill_schema.py` — capture·manifest·recipe/profile에 묶인 durable fill cursor와 불변 대상 metadata. content set 뒤 별도 cursor CAS를 commit하며 완료 재호출은 쓰기·fence·provider가 없다. 계획은 본문 전체 대신 길이 metadata를 보관한다. schema3 sync owner가 view별 vector fill에 쓴다.
- `laya_view_store.py` / `laya_view_reader.py` / `laya_view_schema.py` / `laya_view_values.py` / `laya_view_fts.py` / `laya_view_vectors.py` — schema3 view store의 capture-bound 불변 세대·same-view epoch CAS·세대별 FTS와 pinned lexical·exact reader. 벡터 coverage는 lexical-only 또는 동일 recipe/profile의 전체 eligible member 참조이며 실제 행·set digest를 봉인한다. hybrid는 같은 pin의 lexical 결과를 유지하고 semantic work/deadline만 defer한다. seal과 검색 결과는 구조적 commitment이며 운영 권한을 증명하지 않는다. 운영 권한은 journal의 schema3 endpoint record가 정한다. recall(`laya_reader_dispatch.query_endpoint`), sync 게시(`laya_product_sync_worker`), write-time dedup retrieval(`wiki_compile_retrieval`)이 쓴다. API·상한·실패 의미는 `docs/development-view-candidate.md` 참고.
- `laya_journal_reader.py` — 설치 journal의 reader endpoint 기록과 선택, view pin 및 epoch floor 증명을 담당한다. sync owner의 `resettle_selection`은 설정 또는 vector spec 변경에 맞춰 선택을 재봉인한다.
