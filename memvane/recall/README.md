# Recall

게시된 선택 view를 읽고 검색 결과를 구성한다. 게시 head가 없을 때 다른 view로 대체하지 않는다.

recall은 선택 recall의 판정을 소유하고 평범한 결과 `RecallAnswer`(`types.py`)를 돌려준다. host는 그 결과를 host별 hook 출력으로 렌더링하고 learning capture를 기록한다. trace 필드·진단 note·최종 사유는 host가 넘긴 `RecallTrace` 포트로 보고하며, 이 보고는 답을 바꾸지 않는다.

- `selected_recall.py` — journal이 고른 reader endpoint와 schema3 view의 recall. 설정·provider·vector fallback 판정.
- `dry_run.py` — `api.dry_run_recall(target_root, prompt, *, deadline, use_semantic=True, use_selector=False)`. 프롬프트 recall과 같은 route·reader 규칙으로 한 프롬프트를 읽고 `DryRunRecallResult`(`types.py`)를 돌려준다. route는 `candidate`, `worktree`(`mainRoute`의 reader와 linked worktree 자기 view), `preview`(`initial_build_preview`), 그 밖의 비선택 상태(`route_not_selected`)로 나뉜다. 결과는 4단계를 담는다: lexical(FTS 질의별 bm25 점수·순위), semantic(cosine·순위, 목록 단위 arena 적중은 `timings.arenaHit`), fused(RRF 점수 — 답의 `1/rank`로 바뀌기 전 값), selector(최종 카드, `selectorCheckpoint`, 풀 카드별 선택·탈락 사유). `semanticStatus`·`vectorCoveredMembers`·`vectorEligibleMembers`·`fallbackReason`·`notes`·`timings`도 함께 담는다. 행은 경로와 blob hash만 담고 카드 본문은 담지 않는다.
  dry run은 이벤트 줄과 stderr를 쓰지 않는다. sync·provider owner wake, `ensure_running`, 질의 admission(`admit_query`, 복구 latch를 쓴다), learning capture, `edit-recall-sessions/`를 건드리지 않고 hook budget 대신 호출자 `deadline`만 쓴다. 질의 벡터는 이미 떠 있는 provider worker에 socket으로만 묻는다. 벡터가 없으면 owner state를 읽기만 해서 프롬프트 recall과 같은 fallback 코드를 정한다(non-transient terminal 기록은 `selected_provider_start_failed`, 재시도 창은 보지 않는다). 질의 응답 정체성 불일치는 `selected_provider_identity_transition`으로 거절한다. `use_selector=True`면 `selector_prepared`, plugin 버전, 기존 inference service root와 `inference_version`의 `ready`를 먼저 확인한다. 그중 하나라도 아니면 `select_published`를 부르지 않고 `selector_not_prepared`·`selector_not_warm`을 돌려준다. warm이면 서비스 기동을 거부하는 `ensure_service` 콜백과 `skip_busy`로 묻는다. 거절은 `outcome='refused'`와 고정 코드로 돌려준다.
- `verified_rows.py` — 색인이 검증한 행의 카드 선택(`_select_verified_cards`)과 선택 후 재확인·답 구성(`_serve_verified_rows`). selector에는 검증 pool의 상위 10행을 넘기고 capture는 pool 전체를 받는다. lane별 예산: 프롬프트 recall은 `min(queryTimeout, 3초)`(hook deadline − 1초 안)와 쌍 12개, 편집 recall은 꼬리 deadline과 쌍 91개다. selector가 답한 recall은 주입 카드 가운데 hybrid 상위 3행과 겹치는 수를 `rankedOverlap`으로 남긴다. 근거와 측정 필드는 `docs/continual-learning.md`의 "Selector budget".
- `recall_scope.py` — 한 recall과 그 재시도가 공유하는 상태(journal epoch 하한, project root별 sync wake 1회, writer floor)와 provider owner wake.
  프롬프트 recall에서 provider 기동이 terminal이면 게시된 lexical 목록으로 답하고 `laya_vector_selected_provider_start_failed`를 기록한다. 선택 proof 불일치, owner state 손상, 질의에 응답한 provider의 정체성 불일치와 socket 교체는 recall을 거절한다.
- `domain/rules.py` — 순수 규칙: lexical 질의·RRF 결합(`rrf_ranked`가 RRF 점수와 순서를 내고 `_fuse_verified_lists`가 그 순서에 `1/rank`를 매긴다. 구조적 식별자 — 구조 기호·대소문자 혼합 또는 4자 이상 영숫자 — 는 단독 FTS 질의로도 분리해 일반어 AND 불일치 시에도 정확 일치 카드를 보존), 검증 pool(상위 15행), 답 상한(`topN`과 3 중 작은 값), selector 사유 판정. selector 사유 코드는 `learning.types`의 `SELECTOR_ANSWERS`·`SELECTOR_CANDIDATE_INVALID`를 쓴다.
- 지시문 문장(`keywords.strip_instructions`) — 부정·금지 또는 답 형식 한정 표지를 포함하고 비목록 내용어가 없는 평서문("도구는 쓰지 말고 답만 해 줘.", "Don't use any tools, just answer.")만 lexical 키워드와 프롬프트 recall의 질의 벡터 텍스트(`semantic_query_text`)에서 빠진다. 의문문과 Markdown 코드 펜스 블록은 보존한다. 키워드는 등장 순서로 5개, 일반 lex 문자열은 앞 3개만 AND로 쓰므로(`GENERAL_LEX_TERM_CAP`) 앞에 붙은 지시문이 질문의 드문 토큰을 컷 밖으로 밀고 lex를 지시문 어휘의 AND(대개 0건)로 만들기 때문이다. 내용어가 하나라도 있는 문장은 남고, 프롬프트 전체가 지시문이면 원문을 쓴다. 문장 경계는 줄바꿈과 뒤에 공백이 오는 종결 부호다(`v1.2.3`·`docs/settings.md`의 `.`은 경계가 아니다). 호스트 지시 + 단일 질문 형태(`keywordSpan` `question`)는 그 규칙을 따른다. `build_lexical_terms`의 `instructionFree`와 `recall` 이벤트의 `queryInstructionFree`가 적용 여부를 남긴다. RRF 결합(첫 비지 않은 목록 2배, 1위 +0.05·2~3위 +0.02)은 QMD와 같게 둔다: 지시문이 빠지면 질문의 정확 일치 카드가 lexical 1위로 semantic 단독 1위보다 앞선다.
- `keywords.py`, `reader_dispatch.py` — 질의어 구성과 reader 질의. 프롬프트 recall(`edit_recall() is None`, `MEMVANE_NEED_SIGNALS=off`가 아닐 때)에서는 lexical 단계 직후 AND 질의의 고유 원자 용어를 최대 8개까지 같은 pin에서 개수 전용 읽기 한 번(`_need_signals` → `store.probe_terms`: 본문과 checkout 관측을 읽지 않고, lexical lane이 빼는 wiki 루트 meta 페이지를 세지 않는다. 전체 150ms 가운데 reader 잔여가 2초를 넘는 만큼만 쓴다)으로 세어 `needAtoms`·`needAtomsHit`·`needAtomsRare`·`needRareTopScore`·`needProbeMs`·`needProbeTruncated`를 `recall` 이벤트에 기록한다. 판정이나 recall 결과·순서·주입 변경은 하지 않으며 용어 문자열도 남기지 않는다.
- 질의 벡터(`reader_dispatch.approved_query_vector`) — provider에 hook 프로세스 안에서 recall당 한 번, 2초 안에서 묻는다(자식 프로세스 없음). 긴 프롬프트는 창 최대 4개로 물어 벡터 여러 개가 돌아오고(`memvane/provider/README.md`), exact 검색은 카드별 최고 점수를 쓴다. `recall` 이벤트의 `queryChunks`는 받은 벡터 수, `queryChunksRequested`는 물은 텍스트 수, `semanticOnlyInjected`는 주입한 카드 가운데 lexical 목록에 없던 수다(semantic이 `complete` 또는 `partial`일 때).
- lexical-first view에서도 승인된 provider가 질의에 응답하면 같은 pin의 적격 카드 중 현재 blob SHA, provider의 recipe·profile, chunk set digest가 맞는 set으로 semantic 검색을 한다. 이벤트의 `semantic=partial`은 이 경로를 뜻한다. `vectorCoveredMembers`는 일치하는 set이 있는 카드 수, `vectorEligibleMembers`는 세션 제외 전 적격 카드 수다. 일치하는 set이 없으면 lexical 목록으로 답한다.

recall은 융합 후보별 `store`(Accelerate)·`python`·`lexical` 출처를 보관한다.
host는 이 정보를 capture 입력과 함께 전달하고 learning은
표본을 저장한 뒤 같은 `request_id`의 `learning.capture.sources` 진단 이벤트에
후보 id의 SHA-256과 출처를 기록한다. 학습 표본과 compile 행의 모양은 유지한다.
