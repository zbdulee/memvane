# Wiki Pipeline

`.memvane/compile/wiki-pipeline.sqlite3` 단일 SQLite 원장, 단일 rename 카드 게시, 1회성 1.x → 2.0 마이그레이션을 소유한다.

- **단일 원장 (`store.py`, `schema.py`)**: `compile_jobs`, `verify_jobs`, `refresh_events`, `audit_events`, `cooldowns`, `pipeline_fences`, `publish_txns`, `card_generations`, `suppressions`, `dedup_pairs`, `backfill_checkpoints` 테이블을 트랜잭션(`BEGIN IMMEDIATE`)으로 관리한다. 큐 행 claim·반환·종결은 `queues.py`(`claim_jobs`·`finish_claim`·`recover_dead_claims`)와 `verify_queue.py`(`claim_verify_batch`·`record_verify_verdict`·`finish_verify_job`·`release_verify_claim`)가 맡는다. verify 교체본 이미지는 `verify_jobs.pending_blob`에 있다. `open_pipeline_dir`는 큐 디렉터리 옆의 같은 파일을 연다. 읽기 전용 연결은 `errors._query_only_uri`와 `PRAGMA query_only=ON`을 사용한다. 파일은 application id `0x4D565750`, `user_version` 1, `auto_vacuum=INCREMENTAL`(새 파일은 WAL 전환 전에 설정한다. `auto_vacuum=0`인 파일은 보존 정리가 한 번 `VACUUM`으로 바꾼다)이다. `backfill_checkpoints`는 frozen backfill의 유료 추출 답과 형제 진행을 binding digest마다 한 행으로 담는 재개 checkpoint다.
- **단일 rename 게시 (`publish.py`)**: `.publish-<txid>.tmp`(`O_CREAT|O_EXCL|O_NOFOLLOW`, `fsync`) 준비 → `publish_txns(state='publishing')` 커밋 → 호출자가 넘긴 lock(`lock_context`: `.card-write.lock` → `.topical-publish.lock`) → live 카드 CAS 순서로 진행한다. live가 이미 같은 바이트면 rename 없이 `published`다. 새 카드는 `rename_noreplace`로, 교체는 temp↔live `rename_exchange`로 넣고 밀려난 파일 SHA를 `expected_target_sha`와 대조한다. 다르면(lock 밖 편집기 저장) 다시 교환해 사람 편집을 live로 되돌리고 `conflict_user_edited`로 끝낸다. txn을 닫는 경로는 txn을 먼저 커밋하고 temp를 나중에 지운다. 그래서 그 사이에 멈춘 게시를 복구가 `published_user_edited`로 읽지 않는다. `recover_publishes`는 temp inode·SHA와 live를 대조해 roll-forward, 교환 뒤 대조, `conflict_user_edited`, `published_user_edited`(사람이 다시 편집했거나 지운 카드는 덮어쓰거나 되살리지 않는다), `aborted`로 결정한다. txn마다 따로 처리한다. 경로 검사나 파일 연산이 실패하는 txn(카드 폴더가 symlink로 바뀜, 대상이 디렉터리·FIFO로 바뀜, 상위 경로가 파일로 바뀜, 파일 시스템이 교환을 거절함)은 파일을 건드리지 않고 `aborted`로 닫는다(`PublishOutcome.reason` `unrecoverable:<사유>`). 나머지 txn과 호출자의 verify pass는 계속 진행한다. 원장 오류는 그대로 올린다. 끝으로 60초 넘은 `.publish-*.tmp` 중 열린 txn이 없는 것을 지운다. 닫힌 txn 이름의 temp는 그 txn의 후보 바이트이거나 `published` 교환이 밀어낸 기대 바이트일 때만 지우고, 그 밖의 파일(편집기 저장본, 알 수 없는 파일)은 남긴다. 파일을 읽을 때는 `O_NONBLOCK`으로 열어 FIFO에서 멈추지 않는다. 영속 비교는 `st_dev` 없이 `(st_ino, sha256)`만 사용한다.
- **판정 원장**: `card_generations`는 생성 카드 이력(1.x `generated-manifest.jsonl` 행 모양)을 `target_path`·`source_hash`·`canonical_key` 색인으로 담는다. `publish_card(generation=...)`의 행은 카드가 실제로 놓일 때(`published`·`published_user_edited`, 복구 포함) 같은 트랜잭션에 들어간다. `suppressions`는 같은 원문 body hash의 재추출(`verify`)과 같은 쌍의 재판정(`dedup`)을 막는 유료 호출 가드로, 키마다 마지막 값이 이긴다. `dedup_pairs`는 dedup 후보 쌍 큐다. `audit_events`는 로그 전용이며 어떤 생성·삭제 판정도 읽지 않는다.
- **1회성 1.x → 2.0 마이그레이션 (`migrate.py`)**: `generated-manifest.jsonl`·`verify-skipped.jsonl`·`dedup-skipped.jsonl`만 한 트랜잭션으로 가져오고 같은 트랜잭션에 완료 마커(`migrated_from_v1_at`)를 남긴다. 가져온 manifest 행은 `(줄 번호, 줄 SHA-256)` 키로 한 번만 들어간다. 마커 커밋 뒤 1.x 진행 중 상태(큐·claim·refresh·쿨다운·로그성 jsonl·`tombstones.jsonl`·`.handoff/`)와 위키 숨김 파일(`.first-*`·`.*.pending-*`·`.pc-*`·`.pending-ownership.json`·`.verify-swap-*`)을 지운다. `retired-wiki/`와 `wiki-retrieval/`은 보존한다. 진입은 compile worker 하나다: `wiki_compile_worker._main`이 `.compile-run.lock`을 검증한 뒤 claim 전에 card·mutation lock 아래에서 실행하고 `audit_events`에 `migration` 로그 1행을 남긴다. 실패하면 마커도 claim도 없고 다음 wake가 다시 시도한다. 1.x 잔재가 남은 동안 `needs_v1_migration`은 참이고(마커 뒤 삭제 미완 포함), `selected_execution`의 idle 판정은 할 일이 남은 것으로 보며, `wiki_compile.main`(wiki-compile skill)은 쓰지 않고 `deferred`·`pipeline_migration_pending`을 내며 `laya-compile` wake를 남긴다. 1.x 파일이 없는 프로젝트는 기다리지 않고 첫 worker 회차가 마커를 쓴다.
- **보존 정리 (`retention.py`, `maintain`)**: compile worker가 회차마다 claim 전에 `.compile-run.lock` 아래에서 한 번 돌린다(`_retention_pass`, 결과는 확인하지 않는다). 훅은 관여하지 않는다. 단계마다 최대 500행을 자기 트랜잭션으로 지우므로 중단돼도 다음 회차가 이어서 같은 결과를 낸다. 끝에 `PRAGMA incremental_vacuum(256)`으로 빈 page를 돌려준다.
  - `audit_events`: 종류별로 90일 또는 최신 10,000행 중 먼저 닿는 쪽까지 남긴다. 카드 본문이 들어가는 `dedup_deleted`는 30일 또는 2,000행이다. 같은 시각의 행은 `id` 순서로 자른다.
  - `suppressions`: 기간으로 지우지 않는다(지우면 유료 호출이 다시 나간다). verify 억제는 원문이 모든 수집 root에서 없다고 증명될 때, dedup 억제는 쌍의 한쪽 카드가 없을 때만 지운다. 수집 root가 없거나 `lstat`이 권한 오류이거나 키가 `..`·절대 경로이거나 읽은 뒤 다시 쓰인 행은 남긴다. 같은 원문의 새 본문은 `(kind, key)` 기본 키로 옛 행을 바꾼다. 많을 때는 `pipeline_meta` 커서로 회차마다 한 묶음씩 본다.
  - `card_generations`: 카드마다 최신 5행(`id` 순)만 남긴다. `target_path`가 없으면 `canonical_key`, 그다음 `source_hash`로 묶고 정체성이 없는 행은 그대로 둔다.
  - `cooldowns`: 키마다 한 행이고 만료된 행을 지운다.
  - 끝난 큐 행(`done`·`dropped`), 끝난 게시 txn, `done` dedup 쌍, backfill checkpoint는 30일 뒤 지운다. 같은 대상의 더 오래된 queued verify 행을 supersede하는 terminal 행은 남긴다. 열린 행은 지우지 않는다.
- **조회 CLI**: `entry/run.py wiki-ledger <dedup-pairs|dedup-skip|verify-log|audit <kind>> [--cwd] [--limit N] [--json]`(구현 `memvane/app/entry_commands.py`)는 원장을 읽기 전용으로 연다. 원장이 없으면 빈 목록이고 파일을 만들지 않는다. 출력 키: `dedup-pairs` `{index, pageA, pageB, score}`(`index`는 `wiki-dedup-resolve --index`, `created_ns, pair_key` 순), `dedup-skip` `{pageA, pageB, hashes}`, `verify-log`·`audit`는 로그 payload(최신 `--limit`행, 기본 50).
