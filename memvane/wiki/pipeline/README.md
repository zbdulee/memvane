# Wiki Pipeline

`.memvane/compile/wiki-pipeline.sqlite3` 단일 SQLite 원장, 단일 rename 카드 게시, 1회성 1.x → 2.0 마이그레이션을 소유한다.

- **단일 원장 (`store.py`, `schema.py`)**: `compile_jobs`, `verify_jobs`, `staged_cards`, `refresh_events`, `audit_events`, `cooldowns`, `pipeline_fences`, `publish_txns` 테이블을 트랜잭션(`BEGIN IMMEDIATE`)으로 관리한다. `staged_cards`는 verify `Work` 행(`stage_id`·`queue`·`kind`·`phase`·`closed`·`control_json`·`raw_blob`·`image_blob`·`charged_bytes`)을 담고, control JSON 비교(`cas_work`)로 phase를 바꾸며, `charged_bytes` 합계로 64 MiB(`STAGE_QUOTA_BYTES`) 쿼타를 삽입 트랜잭션에서 강제한다. `open_pipeline_dir`는 큐 디렉터리 옆의 같은 파일을 연다. 읽기 전용 연결은 `errors._query_only_uri`와 `PRAGMA query_only=ON`을 사용한다.
- **단일 rename 게시 (`publish.py`)**: `.publish-<txid>.tmp`(`O_CREAT|O_EXCL|O_NOFOLLOW`, `fsync`) 준비 → `publish_txns(state='publishing')` 커밋 → 호출자가 넘긴 lock(`lock_context`: `.card-write.lock` → `.topical-publish.lock`) → live 카드 CAS 순서로 진행한다. live가 이미 같은 바이트면 rename 없이 `published`다. 새 카드는 `rename_noreplace`로, 교체는 temp↔live `rename_exchange`로 넣고 밀려난 파일 SHA를 `expected_target_sha`와 대조한다. 다르면(lock 밖 편집기 저장) 다시 교환해 사람 편집을 live로 되돌리고 `conflict_user_edited`로 끝낸다. `recover_publishes`는 temp inode·SHA와 live를 대조해 roll-forward, 교환 뒤 대조, `conflict_user_edited`, `published_user_edited`(사람이 다시 편집했거나 지운 카드는 덮어쓰거나 되살리지 않는다), `aborted`로 결정하고, 열린 txn이 없는 60초 넘은 `.publish-*.tmp`를 지운다. 영속 비교는 `st_dev` 없이 `(st_ino, sha256)`만 사용한다.
- **1회성 1.x → 2.0 마이그레이션 (`migrate.py`)**: 기존 `.memvane/compile/*.jsonl`, `*.claimed.*`, `source-refresh-settled.json`, 쿨다운 파일, `.handoff/v1/*`, 위키 숨김 파일을 원장으로 이관하고 정리한다. `.handoff/v1/*`의 진행 중 hold와 `copy-quota/allocated-*`는 가져오지 않고 지우며 publish fence를 세우지 않는다. `.memvane/compile/retired-wiki/`는 보존한다. 진입 경로에는 아직 연결되지 않았다.
