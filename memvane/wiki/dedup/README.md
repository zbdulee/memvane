# Wiki dedup

- `wiki_dedup_scan.py` — retroactive wiki dedup scan. 수명 주기 자식(`wiki_lifecycle.main`)이 수명 주기 run 뒤에 돌린다(새 wake kind 없음, 같은 시간 제한). 선택된 route의 sealed head에서 위키 카드 chunk 벡터 중심점끼리 cosine을 비교해 `config.DEDUP_AUTO_MERGE_THRESHOLD`(0.9) 이상인 쌍을 원장 `dedup_pairs`(`{pageA,pageB,score}`, `queued`)에 넣는다. resolver는 `entry/run.py wiki-ledger dedup-pairs`로 읽는다. 모델·provider·유료 호출이 없고 판정은 resolver 에이전트가 한다. 디스크 바이트가 색인 해시와 같은 카드만 비교하고, 원장 `suppressions`(`dedup`)의 body-hash 억제·`superseded`/`discarded`·이미 큐에 있는 쌍은 건너뛴다. run당 카드 `wiki_source_retire.MAX_CARDS`·변경 카드 50장·`semanticDedup.maxPairsPerScan` 쌍·20초로 묶이고, 비교한 색인 해시를 sync state 디렉터리의 `<key>-wiki-dedup.json`에 남겨 다음 run은 바뀐 카드만 본다. `body_hash`·`load_skip_suppressions`는 resolver·verify worker와 공유하는 SSOT다.
- 카드/wiki 산출물 원자적 쓰기 — **compile·검수·dedup 병합의 카드 게시는 pipeline `publish_card`(temp 파일 + 단일 rename·교환)를 거치고, 그 밖의 카드/wiki 산출물 덮어쓰기는 전부 `memvane.wiki.workspace.api.write_text_atomic`(구현 `atomic_io.write_text_atomic`. 임시파일+fsync+`os.replace`+`copymode`) 하나를 거친다** — `write_text`는 truncate 후 write라 쓰기 실패 시 호출자는 "실패"를 받는데 파일은 이미 잘려 있다(실측: `patch_frontmatter_fields` 40054B→2048B). 절단된 파일도 인덱싱되고 recall이 완결된 요약으로 주입하므로 자동 경로에서는 사람 개입 없는 **조용한 영구 손상**이 된다. 남은 `write_text`는 전부 파일 부재 시 최초 생성이거나 다음 회차가 다시 쓰는 재생성 가능 값이다. `copymode`가 필수인 이유는 `os.replace`가 임시파일 권한(0644)을 남겨 0600 카드가 넓어지는 회귀가 되기 때문이다. 구현을 두 벌로 만들지 말 것. **`wikiPath` 격리 판정(`wsm.wiki_root_of`)도 SSOT다** — 디렉터리 심볼릭 링크와 `wikiPath:"../x"`는 root 밖이라 거부된다(수명 주기·검수·백필 공용).
- `wiki_dedup_judge.py` — **dedup 판정 SSOT.** write-time gate(`wiki_compile.py`)가 쓰는 LLM body-vs-body 판정. `judge_pair`의 호출부는 `wiki_compile.py` 하나다 — retroactive scan(`wiki_dedup_scan.py`)은 judge를 부르지 않는다. extractor와 동일 adapter를 payload `{"task":"dedup"}`로 재사용해 두 카드 본문이 같은 사실인지 묻고 `duplicate`/`distinct`/`unclear` + `reason`/`uniqueToA`/`uniqueToB`를 받는다. vector 점수는 **후보 retrieval**(`semanticDedup.candidateMinScore`, 기본 0.3, 선택된 MemVane 색인의 `selected_execution.wiki_matches`)로만 쓰고 판정은 judge가 한다. judge는 **절대 merge/delete하지 않고 큐에만 넣는다.** **판정 엔진은 신규 후보의 생산 엔진 하나다**(`plan_judge_attempts`, `judgedMode: self`). 생산 엔진은 큐 잡이 정하는 사실이고(모델 출력 `candidate.engine`은 worker가 덮어쓴다), 다른 설치된 CLI로 대신 판정하지 않는다. 생산 엔진이 없거나 해석되지 않으면 `unavailable`(`producing_engine_unavailable`)이다. outcome 3분기: `ok`(판정 유효) / `unavailable`(extractor 미설정·CLI 127·생산 엔진 해석 불가 → 레거시 score-threshold로 degrade) / `transient`(timeout·crash·식힘 중 → 작업 보존). 유료 실패(비127·timeout)는 그 엔진을 원장 `cooldowns`(`dedup_judge_engine`)에 식히고, 두 식힘 기록이 다 실패하면 `cooldownWriteFailed`로 표면화한다. 판정 불가 출력(`invalid_verdict`·`invalid_extractor_json`)은 그 쌍을 `unclear`로 돌리고 judge를 식힌다(같은 입력에서 재현되므로 재과금하지 않는다). 비용 상한은 `semanticDedup.judge.maxPairsPerScan`(기본 8)·`maxPairsPerCompile`(기본 1)이다. write-time gate의 판정은 아직 없는 새 카드와의 비교라 기록하지 않는다. `QMD_DEDUP_JUDGE=off`는 프로세스 단위 kill switch. 표면화의 종점은 `diagnostics()` 한 곳이고 소비자는 `audit_events`의 `candidate` 로그 행의 `judge` 필드다(정상 판정·설정 부재에는 아무것도 쓰지 않는다).
- **판정 불가 출력은 verify와 대칭으로 다룬다**(`UNUSABLE_OUTPUT_REASONS` = `invalid_extractor_json`·`invalid_verdict`, `_unusable_output` ↔ verify `defer_or_drop`). timeout·실행 실패는 진짜 transient라 작업을 보존하지만 이 두 사유는 **같은 입력에서 재현되는** 설정·adapter 오류다: 첫 시도에서 `unclear`+`OUTCOME_OK`로 돌리고 전역 식힘(`cooldowns`의 `dedup_judge`)을 건다. 쓰레기를 내는 adapter는 다음 쌍에도 같은 출력을 내므로 식힘 없이는 그 compile의 판정 예산이 전부 탄다. **transient·식힘·CLI 부재는 판정이 일어나지 않았으므로 `unclear`로 바꾸지 않는다.** retroactive scan 쌍에서 resolver가 둘 다 남기기로 한 판정은 `wiki-dedup-resolve skip`이 원장 `suppressions`(`dedup`)에 두 카드의 body hash와 함께 기록해, 본문이 바뀔 때까지 같은 쌍이 다시 큐에 들어가지 않는다.
- **write-time gate는 `target.exists()`가 false인 모든 신규 카드에 걸린다** (`wiki_compile.py:judge_new_page_duplicate`). `target_reason == "slug"`로 좁히면 extractor가 `targetPath`를 명시한 후보가 dedup을 **완전히 우회**한다 — novel 실측 130/133(97.7%)이 `targetResolution: "explicit"`이다. 단 judge가 없는 머신에서는 retrieval query조차 하지 않고(`wiki_dedup_judge.is_available`가 config만 보고 선판정) 기존 slug-only score gate로 그대로 degrade한다 — 선택된 MemVane 색인이 없으면 retrieval이 빈 목록이라 gate는 열린다(fail-open).
- `wiki_dedup_resolve.py` — resolver 에이전트가 부르는 쌍 해결 CLI(`wiki-dedup-resolve`). `merge`는 지울 카드 B를 지우기 전에 B의 `canonicalKey`·`title`·`aliases`를 남길 카드 A의 `aliases`로, B의 `sources`를 A의 `sources`로 옮긴다(`transfer_labels`). A에 이미 있는 이름표와 출처는 다시 넣지 않는다. 옮길 이름표가 A·B가 아닌 다른 카드의 identity 키와 겹치면 `alias_conflict`로 거절한다. A는 카드 잠금 아래에서 읽은 바이트를 기대값으로 `publish_card`해 바꾸고, 게시가 `published`가 아니면(`label_transfer_failed`) 또는 A에 frontmatter가 없거나 어느 쪽 frontmatter가 해석되지 않으면 B를 지우지 않고 쌍을 큐에 남긴다. 이전이 끝난 뒤에만 복구 사본과 `audit_events`의 `dedup_deleted` 로그(카드 본문 포함, 30일 또는 2,000행 보존)를 쓰고 B를 지운다. 그래서 B의 원문이 다시 compile되면 identity 조회가 A로 이어지고 B는 다시 생기지 않는다.
