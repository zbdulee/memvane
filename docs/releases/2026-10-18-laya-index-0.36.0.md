## Included

- PR #14 Laya origin claim queue crash recovery (in `main`).
- PR #17 exact bundle selection across host caches: the executing host's
  installed bundle is verified on its own and must match the owner's source
  commit, bundle manifest, vector profile and file set. An integration fix,
  not an installed-host L1 pass.
- PR #13 runtime, sync, recall and install boundaries (behaviour-preserving
  refactor; two independent reviews found no blocking defect).
- PR #16 selected stale-recall wake, wiki revision dedup, raw wiki change
  discovery and verifier-cited source lines, with review fixes.
- PR #18 and PR #19 bounded source capacity path: step-bounded catalog,
  returned-candidate verification, vector fill and model-free seal, and the
  worker and host recall on that path. **Off unless the capacity stores
  exist**; the installer creates them only with `capacity_stores=True`
  (default off), so installed behaviour is the full-scan path.
- PR #20: with no cursor, wiki discovery diffs head against its sealed base
  one publish back instead of the lineage root. There is no paid backfill on
  upgrade and no permanent block on long histories. A cursorless start is
  reported as `wikiDiscovery.cursorStarted`.
- PR #21: the embed worker names its content refusals. The capacity fill
  then blocks on that file with its path instead of retrying it every wake.
  This changes a reviewed provider artifact, so the provider proposal must
  be regenerated and reviewed for this candidate.
- The user's existing QMD collections, index and settings are preserved. The
  candidate performs no permanent deletion.
- Current Laya route activation remains pending. It stays off until the exact
  provider, journal and backup gates pass on the installed candidate.
