## Node 22/24/26 CI runner proposal

[`.github/workflows/test.yml`](../.github/workflows/test.yml) currently runs Node 22, 24 and 26 on `ubuntu-latest` with `max-parallel: 1`, `fail-fast: false`, checkout, setup-node, prerequisite version prints and `npm test`. It declares no shared cache, artifact exchange or secrets. [`package.json`](../package.json) routes `npm test` through `scripts/development_guard.py --kind test --max-seconds 1800 -- node --test --test-concurrency=1`; the guard also enforces one file at a time. On Linux its lease is under the runner UID's home. Separate hosted jobs are therefore plausible independent L0 lanes, while each job remains serial internally.

Changing `max-parallel` is a separate CI proposal, **not** part of this plan's implementation. Before a bounded trial, inspect the full `npm test` child graph for external network/rate-limited or real-model work, confirm test-only QMD/lock/temporary state is isolated per job, and confirm required status-check names and billing/concurrency limits. The current workflow shows no cross-job cache, artifact or secret, but it does not prove all test children are free of external effects. Compare job results and actual runner usage before retaining any change; do not assert a speed or cost saving in advance. The change would affect CI scheduling only, not the local heavy lease, each job's 1,800-second limit, L1 coverage or the mandatory host matrix. A Linux Node 26 CI PASS does not satisfy the optional macOS N26 installed-host cell.
