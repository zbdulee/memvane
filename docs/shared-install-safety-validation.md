# Preserving installer safety and synthetic validation

The `setup` skill exposes read-only planning followed by an explicitly approved
preserving installation. Existing files/wiki, global QMD data, model cache and
private history remain in place. Approved project roots share the selected
plugin store/runtime and normal queue maintenance. Optional topical conversion,
Laya preparation and learning retain separate approvals.

Completion requires the canonical project route, ready hook guard, owned healthy
endpoint, durable queue ACK and scoped search. The vector audit additionally
checks active eligible content, the current model/fingerprint, chunk sequence
and total, physical Float32 vector width and finite values. Only defective
target metadata can be invalidated atomically under the common writer/embed
fence. Physical rows and healthy hashes are retained; a defective hash shared
by a foreign collection requires review before mutation.

Approved indexed Markdown collections are hashed before maintenance and again
after readiness; inode/size/mtime/ctime also detect temporary A→B→A edits.
Changed collections alone publish a write-ahead queue intent;
resume checks the recorded snapshot even when no new host hook ran. Source
changes trigger at most three maintenance/readiness passes and then defer with
exit75, retaining normal queued work. This is a bounded stable-source proof,
not a promise that authors stop editing after the completion snapshot.

Bootstrap preparation records generation/probe identity and native step
checkpoints. A native child inherits an exclusive lease, so controller exit
cannot start another writer while that child survives. CPU bootstrap attests
and directly executes the CLI to avoid a launcher dropping the lease. Settings
publication and selected-store maintenance resume their pinned intent. A
partially selected activation preserves state for recovery review; the ordinary
installer does not automatically roll operating data backward.

Denied or unknown process identity is never treated as a dead owner. Lock
reclaim and release share a stable sidecar lease and check owner/inodes. PID
publication uses its original open file; delayed cleanup cannot affect a new
holder. A storage-permission failure preserves the PID marker. Open host
sessions alone are not a writer lease; the live-session flow uses bounded
writer/embed reservation and approved scope rather than fabricated restart or
scheduler-pause acknowledgements.

Portable regressions use disposable synthetic HOME/data, fake QMD/model markers
and mocked endpoint identity where required. They exercise actual worker/queue,
publication, hook guards, metadata repair and subprocess abrupt exit. They never
run paid APIs, user manuscripts, operating DB rollback or real model learning.
The optional native sqlite-vec fixture loads an explicitly supplied existing
extension into an in-memory DB with tiny deterministic vectors; it downloads
nothing and invokes no model. Hardware power loss and a real host upgrade remain
separate validation; synthetic success does not prove a new Linux CI commit.

Relevant suites are `shared-install`, `shared-install-resilience`,
`shared-qmd-setup`, `shared-enrollment`, `setup-upgrade-guard`, `qmd-endpoint`,
`qmd-native-policy`, `live-cutover`, and durable queue/kick regressions. New
upgrade guard cases clear the legacy fixture override. Existing ownerless queue
fixtures use only waited synthetic child exit receipts for dead-PID proof when
the execution environment denies kill-zero. Product EPERM checks are unchanged.

The timeout workload regression uses one fully validated synthetic trace for
two isolated final mutations, checks each predictor and restores only its
disposable SQLite/output checkpoint. Its original timeout remains unchanged.
Runtime downloads, local receipts, machine paths and validation snapshots do
not belong in the plugin source or commit candidate.

## Dedicated HTTP MCP endpoint

New managed daemon startup scans from8584 in steps of1 (default16 candidates,
maximum128). An explicit `QMD_DAEMON_PORT` remains the scan start; candidates
must stay within1024–65535 and an overflowing range fails before spawning.
IPv4 and IPv6 loopback bind probes skip an occupied number without contacting,
adopting or signalling external processes. The actual child bind and identity
remain authoritative; a same-family EADDRINUSE or other-family bind race retries
the next number. Permission/unknown probe results stay closed.

A recorded healthy endpoint with verified PID, executable, runtime/store and
local listener is reused unchanged even if its port predates this new default.
A dead endpoint is recovered through the normal startup scan. Recall, wiki
clients, keepalive, health and log rotation use its proved saved URL/port rather
than guessing the default. A URL override must match that selected endpoint.

The managed QMD wrapper pins Node/CLI identity. `backend/daemon.sh` directly
executes that verified entry as `mcp --http --port <selected-port>` in the same
process watched by the coordinator, avoiding an untracked launcher grandchild.
This is the HTTP MCP daemon, not another independently configured MCP proxy.
