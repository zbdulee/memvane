01 설치와 호스트 hook 경로

사용자가 Claude Code나 Codex에서 평소처럼 작업하면, 호스트가 hook 이벤트를 자동으로 플러그인에 보내고 플러그인은 그 자리에서 응답 경로를 고릅니다.

정상 흐름 한눈에 보기

  1. 입력
    호스트가 hook 이벤트를 보냅니다
    자동즉시

    action, engine, payload(stdin)가 hooks/run-hook으로 들어옵니다.

  2. 처리 ① 가드
    sandbox·headless면 바로 끝냅니다
    자동즉시

    QMD_SANDBOX나 headless 실행이면 아무 작업 없이 종료합니다. Codex의 CODEX_SANDBOX 환경에서는 편집 차단용 gate action만 이 조기 종료에서 제외합니다.

  3. 처리 ② 판정
    route(응답 경로)를 판정합니다
    자동즉시

    payload를 임시 파일에 보관한 뒤, 프로젝트의 .auto-context에 있는 route 기록과 selection marker를 읽기만 해서 경로를 정합니다.

  4. 처리 ③ 분기
    판정 결과에 따라 세 갈래로 나뉩니다
    자동즉시·동기
    candidate
    셸을 Laya 응답 프로세스로 교체해 바로 응답합니다.
    blocked·판정 실패
    exit 3 거부합니다. QMD로 대신 넘기지 않습니다.
    legacy
    설치·합성 호출 검사를 통과하면 기존 QMD 경로로 갑니다. 막히면 작업 없이 끝냅니다.
  5. 결과
    호스트가 응답이나 종료 코드를 받습니다
    자동즉시

    stdout 응답 또는 종료 코드(0·3 등)가 호스트로 돌아갑니다. hook은 route 기록이나 marker를 바꾸지 않습니다.

  6. 다음 동작
    경로를 바꾸려면 설치자 명령을 직접 실행합니다
    사용자 선택hook 밖에서 실행

    route를 게시·철회하는 일은 off-hook 설치자 명령만 할 수 있고, 명시적인 승인 플래그가 필요합니다. 설치 이력은 설치 journal에 기록됩니다.

이 경로에는 큐 대기 단계가 없습니다. 모든 판정과 응답은 hook 호출 안에서 동기로 끝납니다.

자동 경로가 닿지 않는 곳

  • engine=gemini는 받아들이지만, Gemini·Antigravity의 자동 coverage가 보장되지는 않습니다.
  • 공식 Antigravity의 자동 posttool·index·compile은 공식 payload adapter가 생길 때까지 비활성입니다.
  • agy-local-hook-install.sh는 오래된 hook을 정리만 하고, 자동 hook을 설치하지 않습니다.
  • Hermes는 run-hook을 거치지 않는 별도 Python plugin이며, post_tool_call을 관찰만 합니다.

자세히 보기

오류와 복구
  • blocked 또는 판정 실패: exit 3으로 거부하며 QMD fallback은 없습니다. 복구는 설치자 명령(흐름 05 문서)의 activate·recover·restore action으로 합니다.
  • legacy에서 검사 차단: exit 0, 작업 없이 끝납니다.
  • sandbox·headless 감지: 플러그인 파일 처리 전에 종료합니다. topical-stop은 빈 JSON 객체 {}를 출력합니다.
  • update-queued: 소유자가 요청한 history cutover를 확인만 하고, 실패는 무시합니다. history를 고르거나 프로젝트 콘텐츠를 건드리지 않습니다.
  • 설치 계획 거부: .auto-context 아래에 route 기록이나 QMD selection marker가 이미 있으면 설치자가 계획을 거부합니다.
내부 파일과 저장 위치
  • 프로젝트 .auto-context: route 기록, selection marker (hook은 읽기 전용)
  • 설치 state root: install-journal.sqlite, runtime/laya-embed.sock
  • ledger·marker·route 파일 이름은 core/laya_qmd_cutover.py에 정의됩니다. 놓이는 디렉터리는 발췌만으로 확정되지 않습니다.
  • local trial marker가 있으면 QMD_AUTO_COMPILE_DISABLED를 export합니다. runtime env 파일에서는 검증된 대입만 export합니다.

이 프로젝트의 용어

route
hook 이벤트를 어느 경로로 처리할지 정한 값. legacy·candidate·blocked 중 하나. laya_index_host_route.py classify-hook
candidate
Laya 응답 경로로 처리하는 route. 셸을 동기 응답 프로세스로 교체. laya_host_response.py serve-stdin
blocked
처리를 거부하는 route. 판정 실패도 같은 결과(exit 3)이며 QMD fallback 없음.
legacy
기존 QMD 경로로 진행하는 route. 가드 통과 후 기존 backend로 dispatch.
QMD
기존 backend 경로. legacy일 때만 사용. 관련 변수 QMD_SANDBOX, QMD_AUTO_COMPILE_DISABLED
Laya
candidate route가 응답을 맡기는 새 경로. hook에서는 core/laya_host_response.py로 진입.
.auto-context
프로젝트 안에서 route 기록과 selection marker가 놓이는 위치. hook은 읽기만 함.
selection marker
QMD 선택 상태를 나타내는 표시 파일. 설치자만 변경. laya_qmd_cutover.py
setup_guard · synthetic gate
legacy action이 backend로 가기 전 통과해야 하는 설치 상태 검사와 합성 호출 차단 검사. setup_guard.py, synthetic_invocation_gate.py
off-hook 설치자
hook 밖에서 사용자가 실행하는 설치 명령. plan·prepare·activate·recover·restore action, --approve-* 필요. core/setup_entry.py
설치 journal
설치 state root 아래의 설치 이력 DB. install-journal.sqlite
update-queued
history cutover 요청을 확인만 하는 hook action. legacy 가드 대상에서 제외. context_learning_host_ack.py
history cutover
소유자가 요청한 history 전환. hook은 이를 확인만 하고 직접 수행하지 않음.
local trial marker
로컬 시험 상태 표시. 있으면 자동 compile을 끔(QMD_AUTO_COMPILE_DISABLED).
payload adapter
공식 Antigravity payload를 받아들이기 위한 변환기. 아직 없어 자동 경로 비활성.
observer-only
Hermes plugin이 post_tool_call을 관찰만 하고 route·enqueue·compile 경로에 참여하지 않는다는 뜻.
