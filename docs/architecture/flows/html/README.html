전체 목차

기능별 아키텍처 흐름도 — 전체 목차

개발자가 플러그인 사용에 동의하고 자동 위키 생성이 켜진 프로젝트의 원문을 고치면, 변경이 위키 카드로 정리됩니다. 색인과 검색·주입은 이어지는 별도 단계입니다.

번호는 읽기 순서입니다. 1–3은 주요 사용 흐름이고, 학습(4)과 이관(5)은 각각 별도로 선택하는 흐름입니다.

  1. 1 설치·동의와 호스트 훅 사용자 선택
    입력
    설치 후 프로젝트 동의, 훅 신뢰
    처리
    호스트 이벤트가 훅을 실행
    결과
    이후 단계가 훅으로 시작될 수 있음
    다음
    원문 변경을 기다림 → 2
  2. 2 원문 변경 → 위키 카드 자동 감지큐 대기 (비동기)
    입력
    원문 파일 변경
    처리
    변경 감지 → 비동기 추출·검증, 큐 경유
    결과
    위키 카드 (발췌·원문 위치 링크 포함)
    다음
    위키 색인 → 3
  3. 3 위키 색인·검색·주입 위키만 색인원문 열람은 호스트 선택
    입력
    위키 카드
    처리
    Laya 위키 전용 저장·검색
    결과
    선택된 카드와 출처 링크를 주입
    다음
    학습(4)이나 이관(5)이 필요하면 각각 별도로 참고
  4. 4 학습 자원 승인 필요완료 주장 아님
    입력
    합성 준비
    처리
    자원 승인 → 학습·모델 선택 (별도 단계)
    결과
    승인된 단계까지만 진행
    다음
    검색·이관의 필수 선행 단계는 아님
  5. 5 이관·전환·백업·복구 운영 전환 완료 아님
    입력
    기존 QMD 데이터
    처리
    QMD 원본 보존, 위키 전용 후보 작성
    결과
    최초 쓰기 전후 각각 복구 경로
    다음
    문제 시 복구 분기 (05 페이지)

이 자료는 설계·구현 이해용입니다. 아직 끝나지 않은 실제 호스트 QA의 통과 증명이 아닙니다.

어떤 질문에 어느 페이지를 열까

01 설치·설정과 호스트 훅“설치 후 동의와 훅 신뢰는 어떻게 되고, 어떤 호스트 이벤트가 훅을 실행하나요?” 02 원문 변경에서 위키 카드까지“원문을 고치면 언제, 어떤 큐를 거쳐 위키 카드가 생기나요?” 03 위키 색인·검색·주입“Laya는 무엇을 저장·검색하고, 에이전트에게 무엇이 주입되나요?” 04 학습“합성 준비, 자원 승인, 학습·모델 선택은 어떻게 나뉘나요?” 05 이관·전환·백업·복구“QMD에서 옮길 때 원본은 어떻게 보존되고, 실패하면 어떻게 되돌리나요?”

경계·검증 상태 (펼쳐 보기)

데이터 경계: 원문 · 위키 카드 · QMD · Laya
  • 원문 파일: 위키 생성과 출처·최신성 확인의 입력입니다.
  • 위키 카드: 정리된 발췌와 원문 위치 링크를 그대로 담습니다.
  • Laya: 독립 문서 색인·검색에는 위키만 들어갑니다. 원문은 별도로 색인되지 않습니다.
  • 선택된 Laya 설치는 별도 프로세스에 임베딩 모델을 유지합니다. SQLite 검색은 질문마다 Python에서 실행하며 상주 검색 서버가 아닙니다. 모델 준비·자원 보류는 검색 성공이 아닙니다.
  • QMD: 이관 시 원본을 보존하며, Laya 위키 색인과는 별개입니다.
  • 호스트 에이전트가 링크를 열어 원문을 읽을지는 플러그인 밖의 결정이며, 플러그인 통과 조건이 아닙니다.
교정 시 확인된 사항
  • Antigravity 자동 훅은 현재 비활성 상태입니다.
  • 원문은 Laya 검색에 별도 색인되지 않습니다.
  • 비동기 큐의 dropped 의미를 확인했습니다. 자세한 뜻은 02 페이지를 보세요.
  • 상대 코드 링크와 미완료 호스트 QA 표시를 확인했습니다.

이 프로젝트의 용어

호스트
플러그인을 실행하는 에이전트 환경(예: Antigravity). 이벤트로 훅을 부르고, 원문 링크를 열지 스스로 정합니다.
훅
호스트 이벤트에 반응해 실행되는 플러그인 진입점. 사용자가 신뢰해야 실행됩니다. 상세: 01 페이지.
프로젝트 동의
프로젝트 단위로 플러그인 사용을 허락하는 사용자 선택. 상세: 01 페이지.
위키 카드
원문에서 추출·검증해 만든 정리 문서. 발췌와 원문 위치 링크를 포함하며, Laya에 색인되는 유일한 대상입니다.
큐
추출·검증을 비동기로 처리하는 대기열. 상태 dropped가 있으며 뜻은 02 페이지 참조. 임의의 전체 비움을 보장하지 않습니다.
Laya
위키 전용 저장·검색 색인. 원문 본문을 저장·검색·주입하지 않습니다. 상세: 03 페이지.
임베딩 모델 소유 프로세스
선택된 설치의 로컬 모델을 유지하는 별도 프로세스. 같은 사용자·설치·provider·모델 지문에만 재사용됩니다. OS 부팅 서비스나 Laya 검색 서버는 아닙니다. 상세: 03 페이지.
주입
검색에서 선택된 위키 카드와 출처 링크를 호스트 에이전트 맥락에 넣는 단계.
QMD
이관 전 기존 저장소. 이관·전환 중에도 원본이 보존됩니다. 상세: 05 페이지.
위키 전용 후보
이관 시 QMD 원본과 별도로 만드는, 위키만 담는 전환 후보.
최초 쓰기
전환 대상에 처음 기록하는 시점. 그 전과 후의 복구 방법이 다릅니다.
guard
작성·교정 결과를 확인하는 검증 기록. 아래 출처의 식별자로 표시됩니다.
