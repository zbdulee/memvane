02 원본 소스에서 위키 카드까지

사용자가 원본 Markdown(raw) 노트를 고치거나 sync를 실행하면, 변경 정보가 큐에 쌓이고 나중에 worker가 그 노트로 위키 카드를 만듭니다.

  1. 입력 / 행동 원본 Markdown이 바뀝니다 편집 hook: 자동sync: 사용자 실행 가능 편집 hook 이벤트(run-hook 경유 엔진만) 또는 sync가 감지한 변경 목록, 둘 중 하나로 들어옵니다. 공식 Antigravity의 자동 편집 이벤트는 현재 이 경로로 들어오지 않습니다(01 참조).
  2. 처리 ① 동기 enqueue 게이트가 받을지 말지 정합니다 즉시자동LLM 호출 없음 이벤트 범위, compile gate, queue 경로를 검사합니다. 거부되면 queued 0과 사유만 돌려줍니다.
  3. 저장 위치 메타데이터만 큐에 기록합니다 즉시 기록이후 큐 대기 compile source queue(.auto-context/compile)에 append합니다. 편집 이벤트는 pending refresh도 남깁니다. 그다음 wake를 요청합니다. 본문을 복사해 두는 것이 아니라 경로·hash 같은 메타데이터만 기록합니다.
  4. 처리 ② 비동기 worker worker가 job을 하나씩 확인합니다 큐 대기 후 비동기자동 process_job이 route identity, 경로 범위, 안정 snapshot, 비용 가드를 차례로 통과시킵니다. 하나라도 걸리면 모델을 부르지 않고 candidate ledger에 기록합니다.
  5. 결과 extractor가 위키 카드를 만듭니다 자동모델 호출 경계 extractor를 실행해 위키 카드(.auto-context/wiki)와 verify 대상을 만듭니다.
  6. 다음 동작 Laya 색인 sync는 따로 진행됩니다 별도 단계(03) 카드가 바뀐 것은 이후 Laya 색인의 입력이 될 뿐입니다. compile 완료가 색인 반영이나 recall 반영을 뜻하지 않습니다.

혼동하기 쉬운 네 가지

  • 원문 파일(raw): 카드 생성의 입력이자 path·hash freshness 메타데이터의 기준입니다. Laya가 원문 본문을 따로 저장·검색·주입하지 않습니다.
  • 위키 카드: extractor가 만든 결과물입니다. 카드 안의 적절한 발췌와 원문 위치 링크는 정상입니다.
  • Laya 위키 전용 색인: 위키 카드를 대상으로 하는 별도 단계(03)입니다.
  • QMD: 기존 검색·색인 저장소입니다. 위키 생성 완료와 QMD 또는 Laya 색인 반영은 서로 다른 단계입니다.

카드 속 원문 링크를 호스트가 실제로 열어 읽을지는 호스트의 선택이며, 플러그인 통과 조건이 아닙니다.

오류와 복구

enqueue 단계에서 멈추는 경우
  • sync 경로: compile_gate, _safe_queue_path, 후보 산출 중 하나에서 걸리면 사유만 반환합니다.
  • 편집 경로: 이벤트 종류, generated story scope, postToolUse 설정, compile gate, queue 경로를 순서대로 봅니다. record_pending_refresh가 None이면 enqueue하지 않습니다.
  • sandbox이면 즉시 0을 반환합니다. 비었거나 잘못된 JSON 입력은 무시합니다.
  • 수동 sync는 이번 wake 대상 행만 revision hash를 계산해 같은 revision 재시도를 알아봅니다. hash가 없는 legacy 행은 억제하지 않고 유지합니다.
worker 단계에서 멈추는 경우
  • selected route identity가 바뀌었거나 route가 사라짐 → skipped 기록, job은 보존합니다.
  • 경로 탈출, .md 아님, 숨김 경로, 컬렉션 불일치, compile source role 아님 → extractor_failed 기록.
  • source 읽기 실패 → candidate ledger에 기록. 읽기는 maxSourceChars 한도 안에서 decode합니다.
  • 비용 가드: verify inconclusive suppression, 또는 selected route에서 이미 compile된 revision이면 skip을 기록합니다. 두 번째 가드는 pending이 없고 partialCompile이 아닐 때만 적용됩니다.
trial 환경의 자동 compile 차단

local trial marker가 있으면 run-hook이 QMD_AUTO_COMPILE_DISABLED를 설정합니다. 자동 compile이 source 텍스트를 모델로 보내지 않게 하기 위해서입니다.

구현됨 vs 미검증

현재 상태
  • 구현됨: 위 단계 1~5의 enqueue·worker 게이트 코드(커밋 f89b141).
  • synthetic QA: release-agent-qa.md에 증거가 있지만, selected route의 end-to-end compile 통과를 뜻하지 않습니다.
  • 미통과: 해당 호스트 QA는 통과하지 않았습니다.
  • 발췌 범위 밖: extractor 이후 카드 기록(wiki_compile)과 verify 처리는 단계 5 하나로 요약했습니다.
  • 남은 위험: enqueue와 snapshot 기록 사이에서 실패하면 중복 재시도가 일어날 수 있습니다.

이 프로젝트의 용어

raw (원본)
사용자가 직접 쓰는 원본 Markdown. 카드 생성 입력이자 freshness 기준.관련: enqueue_payload, enqueue_changed_sources
compile gate
enqueue 전에 compile 허용 여부를 판단하는 검사.관련: compile_gate, _safe_queue_path
compile source queue
compile할 원본의 메타데이터가 쌓이는 큐.위치: .auto-context/compile
pending refresh / freshness pending ledger
편집 이벤트로 아직 반영 안 된 변경을 기록. worker가 최신 미해결 항목을 바인딩.관련: wiki_freshness.record_pending_refresh
wake
worker에게 compile을 시작하라고 알리는 요청.관련: wiki_selected_laya.request_compile
compile worker
큐의 job을 비동기로 처리하는 단계.관련: process_job(wiki_compile_worker.py)
selected route / route identity
현재 선택된 compile 대상 경로와 그 식별값. 바뀌면 job을 보존하고 건너뜀.상태: skipped
안정 snapshot
읽는 도중 바뀌지 않은 원본 내용과 그 hash.관련 설정: maxSourceChars
비용 가드
모델 호출 전 불필요한 실행을 막는 두 검사: verify inconclusive suppression, 이미 compile된 revision.관련 설정: partialCompile
compile candidate ledger
worker의 skip·실패 결과를 남기는 기록.상태: skipped, extractor_failed
extractor
원본에서 카드를 뽑아내는 모델 호출 경계.
위키 카드
extractor 결과물. 발췌와 원문 위치 링크를 담을 수 있음.위치: .auto-context/wiki, 관련: wiki_compile
verify 대상 / verify queue
생성된 카드 중 검증이 필요한 목록. worker 반환값에 포함.
Laya 색인
위키 카드 전용 색인. 이 흐름 밖의 별도 단계(03).
local trial marker / QMD_AUTO_COMPILE_DISABLED
trial 환경 표시. 있으면 run-hook이 이 변수를 설정해 자동 compile이 원문을 모델로 보내지 않게 함.위치: hooks/run-hook
