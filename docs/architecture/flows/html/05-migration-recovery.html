05 · QMD 이관과 복구

프로젝트 소유자가 지금 쓰는 QMD 색인을 Laya 위키 색인으로 바꾸려고, 설치자 명령으로 이관을 계획하고 빌드가 끝나면 직접 승인해 전환합니다.

hook이 아니라 설치자 명령으로만 진행됩니다(off-hook). 아래는 구현된 코드 경로이며, 실제 호스트의 cutover·복구 QA는 아직 완료되지 않았습니다.

표시: 사용자 선택자동즉시큐 대기

  1. 이관 계획 세우기

    사용자 선택즉시
    행동
    설치자가 이관 계획을 요청합니다.
    처리
    QMD를 읽기 전용으로 보고 검토 제안을 만듭니다. 원고 본문은 넣지 않습니다.
    결과
    본문 없는 검토 제안. QMD는 계속 선택된 채 색인합니다.
    다음
    provider 검토로 넘어갑니다.

  2. provider 검토

    사용자 선택즉시
    행동
    설치자가 검색 모델과 실행 환경의 제안을 검토합니다.
    처리
    계획에 쓸 provider를 검토합니다.
    결과
    검토한 plan·provider hash가 다음 단계의 기준이 됩니다.
    다음
    초기 빌드 준비.

  3. 비활성 초기 빌드 등록

    사용자 선택등록 즉시빌드는 큐 대기
    행동
    설치자가 비활성 후보 빌드를 준비합니다.
    처리
    활성화는 하지 않고 초기 빌드만 등록합니다. 검토한 hash가 바뀌었으면 거부합니다.
    결과
    백그라운드 빌드 작업이 대기열에 올라갑니다.
    다음
    worker가 빌드를 진행합니다.

  4. 비동기 빌드 → sealed

    자동비동기
    처리
    worker가 빌드합니다. route는 선택하지 않습니다. bind가 정착되지 않았거나 owner가 busy면 deferred로 두고 다시 시도합니다.
    저장
    candidate catalog binding store
    다음
    sealed가 되면 finalize 가능.

  5. finalize로 bind

    사용자 선택즉시
    행동
    설치자 명령 finalize-index-origin
    처리
    봉인된 빌드를 cutover에 묶습니다(bind).
    저장
    qmd-cutover.json ledger와 selection marker
    다음
    bind 뒤 QMD가 바뀌었으면 retired, 새 generation 필요.

  6. 명시 승인으로 활성화

    명시 승인 필요게시 즉시sync는 wake 요청
    행동
    설치자 명령 activate-index-origin + 승인 플래그
    처리
    ledger, fresh bound generation, QMD 증거를 확인합니다. 하나라도 맞지 않으면 거부하고 QMD 선택을 유지합니다.
    저장
    laya-index-route.json 게시
    다음
    sync wake를 한 번 요청합니다. 선택된 설치의 별도 모델 소유 프로세스가 차가우면 off-hook 경로에서 준비하고 작업을 보류합니다. 준비 후 위키를 색인해도 모델은 유지됩니다. wake 요청·준비 중은 검색 성공이 아닙니다. 이후 QMD 변경은 보고만 합니다.

이관 중에도 지켜지는 것

  • QMD source는 논리적으로 바뀌지 않습니다. 단, 일관 backup이나 읽기 reservation 중 SQLite WAL sidecar(-wal·-shm)가 생길 수 있습니다.
  • 원본 QMD DB와 backup은 삭제되지 않습니다.
  • 별도로 설치된 global QMD는 이 흐름의 대상이 아닙니다.
  • 계획은 모델·backup·candidate·plugin cache를 건드리지 않습니다.

오류·복구·근거 (펼쳐 보기)

되돌리기(restore)와 중단 정리(recover)
  • recover recover-index-origin: 중단된 cutover를 정리하고 ledger에 반영합니다. 결과가 active면 sync wake를 요청합니다.
  • restore restore-index-origin: 첫 selected write 이전에만 가능합니다. restored_qmd로 CAS를 한 번 수행하며 재시도하지 않습니다.
  • CAS 성공: QMD origin으로 복귀합니다. 이번 cutover가 게시한 route 파일만 철회합니다. 모델 소유 프로세스의 정리는 소켓 부재와 owner lock 해제 둘 다 확인합니다. 정리가 남으면 embedServiceCleanup: pending을 별도로 보고하며, 복원 완료를 모델 정리 완료로 과장하지 않습니다.
  • CAS 실패: recovery_required를 보고합니다. QMD·backup·candidate·ledger·marker는 그대로 둡니다.
  • 첫 selected write 이후: QMD로 되돌리지 않고 전진 복구 규칙을 적용합니다.
  • marker는 중단된 selected route가 legacy로 조용히 넘어가지 않도록 막습니다.
거부되는 경우
  • 계획: 이미 selection이 있음, settings가 canonical이 아님, raw+wiki 구성이 아님, 루트가 겹침, QMD가 managed·selected 상태가 아님.
  • prepare: 검토한 plan·provider hash가 바뀜.
  • 초기 빌드: 프로젝트가 이미 선택된 상태면 오류.
  • finalize 이후 QMD digest 변경: 다시 bind하지 않고 retired, 새 generation 요구.
  • activate: ledger 없음, retired, 증거 불일치 → 거부, QMD 선택 유지.
  • route 게시 전 raw baseline이 바뀌면 재계획을 요구합니다.
  • 선택 후 모델 기동이 자원상 보류되거나 제한 재시도 끝에 실패하면 해당 요청을 검색 PASS로 세지 않습니다. 모델은 OS 부팅 서비스로 등록되지 않습니다.
관련 파일 이름
  • QMD DB(플러그인이 선택한 것) · QMD backup
  • candidate catalog binding store
  • qmd-cutover.json ledger · selection marker
  • laya-index-route.json

구현됨 vs 미검증
  • 구현 경로: 기존 이관·recover·restore 경로와 현재 후보의 별도 임베딩 모델 owner·복원 정리 확인. 새 모델 owner는 최종 후보 검증 전이므로 설치 후 동작 통과를 뜻하지 않습니다.
  • synthetic QA: release-agent-qa.md. 운영 cutover·활성화·recover·restore·실제 route 선택의 통과를 뜻하지 않습니다.
  • 미검증: 실제 호스트의 QA cutover와 복구. 운영 전환은 이 QA의 실행 결과가 아닙니다.
  • 계획 단계: 플러그인 소유 QMD runtime의 ownership manifest 정리와 데이터 이전. 운영 경로 변경은 아직 없습니다.

이 프로젝트의 용어

QMD
이관 전 프로젝트가 선택해 쓰던 기존 색인 origin. 대상은 플러그인이 관리·선택한 QMD DB뿐이며 global QMD는 제외. laya_qmd_cutover.py
Laya 색인
이관 후 선택되는 Laya 위키 전용 색인 origin. 원문 파일 본문을 별도로 저장하는 곳으로 보지 않습니다.
off-hook (설치자 명령)
hook이 아니라 설치자가 직접 실행하는 명령 경계. *-index-origin, review-index-provider
cutover
QMD에서 Laya로 색인 origin을 바꾸는 한 번의 전환. phase는 prepared·switching·active·restoring·restored·retired.
sealed
비동기 초기 빌드가 끝나 finalize할 수 있는 상태. run_initial_build
deferred
bind 미정착 또는 owner busy로 빌드를 미룬 상태. wake를 유지해 재시도.
candidate
초기 빌드 결과가 담기는 catalog binding store. 활성화 전에는 선택되지 않음.
bind / finalize
sealed 빌드를 cutover에 묶는 단계(v3 bind prepared). finalize-index-origin
generation
bind된 빌드 세대. 활성화에는 fresh bound generation이 필요.
retired
bind 후 QMD digest가 바뀌어 더 쓸 수 없는 cutover. 새 generation 필요.
ledger
cutover 상태 기록 파일 qmd-cutover.json.
selection marker
중단된 selected route가 legacy로 조용히 넘어가지 않게 막는 표식.
route 파일
활성화 때 게시되는 laya-index-route.json. restore 시 이 cutover가 게시한 것만 철회.
wake
sync worker에 작업을 알리는 요청. 활성화 시 한 번.
임베딩 모델 소유 프로세스
선택된 설치의 로컬 모델을 별도로 로드해 유지하는 프로세스. 동일 사용자·설치·provider·모델 fingerprint가 맞을 때만 재사용하며, 동기화가 끝나도 유지됩니다. Laya SQLite 검색 서버나 OS 부팅 서비스가 아닙니다.
selected write
Laya route가 선택된 뒤의 쓰기. 첫 발생 이후 restore 불가.
restored_qmd
restore가 CAS로 기록하는 대상 상태. 재시도 없음.
recovery_required
restore CAS 실패 시 보고되는 관측 결과. 파일은 모두 보존.
전진 복구 규칙
첫 selected write 이후 QMD로 되돌리지 않고 적용되는 기존 복구 규칙.
raw baseline
route 게시 전에 seed되는 raw 기준선. 바뀌면 재계획. laya_wiki_discovery.py
qmdChangedAfterActivation
활성화 이후 QMD가 바뀐 것을 보고만 하는 항목.
