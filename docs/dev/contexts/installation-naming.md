# 설치·정리와 내부 명명

임베딩 모델과 학습 추론은 사용자당 하나인 `core/laya_resident_service.py` 프로세스가 호스팅한다. 서비스는 설치별 socket과 owner lease를 통해 worker를 공유한다.
### 설치 / cleanup
Claude·Codex는 marketplace plugin install이 제품 경로다. 제품용 `install.sh`/`uninstall.sh`는 없다. AGY는 공식 PostToolUse payload adapter 전까지 자동 hook을 설치하지 않는다.

live `v1/`에 쓰는 setup과 writer는 실행 플러그인 루트가 Claude 또는 Codex의 `plugins/cache/<marketplace>/memvane/<version>` 경로에 있어야 한다. `MEMVANE_TEST_ALLOW_UNINSTALLED_ROOT=1`은 격리 시험 전용이다.

새 머신의 Laya embed runtime은 `setup_entry.py provision-index-runtime --approve-index-runtime-download`가 만든다(`core/laya_embed_runtime.py`). Node는 `PATH`를 먼저 보고 mise/fnm/nvm/volta/asdf/Homebrew/system 설치 순으로 찾되 메이저 22/24/26의 실제 바이너리만 받는다(버전 매니저 shim은 거절). `locks/laya-embed-runtime`(node-llama-cpp 3.18.1 + prebuilt `@node-llama-cpp/mac-arm64-metal`)를 `npm ci --ignore-scripts`로 설치하고, GGUF는 `https://huggingface.co/ggml-org/embeddinggemma-300M-GGUF/resolve/main/embeddinggemma-300M-Q8_0.gguf`에서 받아 sha256 `f470220f84b6235197541352d22f10bf00098a8242c18eaacea9c8a4add557bc`과 일치할 때만 채택한다(`--provider-model-file`로 같은 GGUF의 로컬 사본 지정). 결과는 `~/.local/state/memvane/v1/embed-runtime`의 세대 디렉터리와 `active.json`·`previous.json`이다. `gc-index-runtime`은 active·previous·`~/.local/state/memvane/v1/installs/*/production-provider-attestation.json`이 가리키지 않는 세대를 나열하고 `--approve-index-runtime-gc`가 있을 때만 지운다(attestation의 과거 `profileDependencyClosure` 행은 보지 않는다).


### 이름과 내부 명명
- 제품 이름은 MemVane, 플러그인 id는 `memvane`, marketplace는 `memvane-marketplace`, 저장소는 `zbdulee/memvane`이다. skill id는 `memvane:<skill>`, 색인 DB의 사용자용 이름은 memvane-db, hook·안내 메시지 태그는 `[memvane]`이다.
- 사용자별 루트는 `core/memvane_paths.py`가 정한다: 상태 `~/.local/state/memvane/v1`(설치별 state root, `embed-runtime`, `service`, `initial-builds`, `auto-context` 로그·scan state: 프로젝트 폴더와 별개인 사용자별 디렉터리라 이름이 그대로다), 지원 디렉터리 `~/Library/Application Support/memvane`(그 밖의 OS는 `~/.local/share/memvane`), 설정 `~/.config/memvane`, 캐시 `~/Library/Caches/memvane`·`~/.cache/memvane`. 새 설치·온보딩은 이 루트에만 쓴다.
- 내부 명명은 `core/laya_*.py` 모듈, Laya 엔진 용어, `configFormat` 값 `auto-context-dir`, `QMD_*` 환경 변수를 쓴다. 프로젝트 포인터는 `.memvane/route.json`과 `.memvane/selection.json`이다.
- 프로젝트 폴더는 `.memvane/`다. 설정, `wiki/`, route·selection·lock·`compile/` 런타임 파일을 이 폴더에 둔다(`core/project_dir.py`).
- resident service는 사용자별 서비스 루트에서 동작한다. worker는 바인딩과 진행 중 요청이 없으면 `RECLAIM_SECONDS` 뒤 정지한다. 바인딩은 `OWNER_RECHECK_SECONDS` 간격으로 소유를 재증명하며, owner 잠금 경합이면 바인딩과 socket을 유지한다. `LAYA_SERVICE_TIME_SCALE`은 fixture 전용 내부 환경 변수다.
- wiki-dedup resolver는 프로젝트별 run-lock을 사용한다.
- 프로젝트 단위 lock 이름은 `laya-qmd-cutover-operation.lock`, `.topical-publish.lock`이다.
- 위키 카드 소유 표시: 새 카드는 `createdBy: memvane`과 `> Auto-generated by MemVane` 상투구를 쓰고, 읽는 쪽은 `qmd-auto-context`도 같은 소유로 본다(`wiki_markers.CREATED_BY_NAMES`·`AUTO_DISCLAIMER_PREFIXES`).

런타임 선택은 provider·worker 파일과 모델·런타임 정체성을 확인한다.
