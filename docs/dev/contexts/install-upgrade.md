# 설치 증명과 번들 업그레이드

- `laya_ledger_common.py` — 선택 ledger 공용 primitive(비공개 JSON 읽기·쓰기, ledger lock, 프로젝트 단위 operation lock `laya-qmd-cutover-operation.lock`, multi settings preflight). fresh-wiki ledger·`_select_route`·active/bound/inactive 업그레이드가 이 모듈을 import한다. state root에 QMD-origin ledger(`qmd-cutover.json`)가 남아 있으면 `refuse_qmd_origin`이 `qmd_origin_detach_required`로 거절하고, `_select_route`는 QMD-origin marker를 같은 사유의 `blocked`로 분류한다. lock 파일 이름은 구버전 호스트 사본과의 상호 배제 계약이라 바꾸지 않는다.
- `laya_product_install.py`의 fresh prepare(`prepare_fresh_wiki_origin`)는 review digest를 확인한 뒤 두 state base 아래 모든 설치 디렉터리(중단 뒤 재실행에 대비해 자기 설치 포함)의 소유자 전용 attestation을 donor 후보로 읽고 `reattest`로 내용 동등성을 증명한다. 동등한 donor가 있으면 새 설치는 기존 설치들의 벡터 프로필로 합류하고 attestation에 `profileDependencyClosure`를 싣는다(결과의 `profileDonor`). 봉인된 번들은 자기 봉인 프로필의 donor만 받는다. 미봉인 번들에서 서로 다른 동등 프로필(review 자신의 프로필을 가진 설치도 센다)이 둘 이상이면 `fresh_profile_donor_ambiguous`로 거절하고, 다른 동등 프로필이 없으면 review 프로필을 그대로 쓴다. 봉인 메타데이터가 검증되지 않는 번들은 미봉인으로 보고 adopt가 다시 봉인한다. review 경로의 프로필은 런타임 절대 경로에서 파생되므로, 이 합류가 없으면 옮겨진 런타임에서 새 설치가 봉인 번들에 `installed_candidate_already_owned`로 거절되거나 미봉인 번들을 기존 설치가 업그레이드할 수 없는 프로필로 봉인한다.
- 번들 불일치 중 읽기 — 전체 증명이 번들 정체성(`laya_install_journal.BUNDLE_DRIFT_CODES`)에서만 실패하면 `verify_selected_route_read_only`가 route·journal·저장소 incarnation·봉인된 attestation만 다시 증명하고, recall은 마지막 게시 세대를 읽기 전용으로 제공한다(warm owner가 없으면 lexical만. schema3 endpoint는 이 읽기 전용 증명에서 query vector를 요청하지 않고 lexical로 답한다. 번들 증명이 서는 연결 워크트리 읽기는 vector를 쓴다). sync·compile·index wake는 기록하지 않고, SessionStart는 실제 사유를 담은 한 줄 안내를 낸다. hook stderr는 `JournalEvidenceError` 코드를 그대로 보고한다.
