# 설정과 경로

- `config.py` — 프로젝트 폴더의 `settings.json` 로드 + 기본값 병합(`.memvane/` 먼저, 없으면 `.auto-context/`, `project_dir.settings_path`). `wikiPath`·`collectionPaths` 값이 두 폴더 이름 중 하나로 시작하면 활성 폴더로 맞춘다. 숫자 필드(minScore/topN/queryTimeout) 보수적 coercion, 실패 시 기본값. legacy novel 컬렉션명(`*-manuscript`/`*-plot`)은 `lexicalPatterns:["ep"]` 자동 활성화. 키가 `name`·`skipPaths`뿐인 canonical `settings.json`(minimal settings)은 `expand_minimal_settings`가 legacy 모양(raw `"."` + wiki `<활성 폴더>/wiki`, collection 이름은 `name`의 slug와 slug-wiki, `wikiOnly`, host builtin auto-wiki compile, contextLearning 켜짐, `indexing:true`)으로 펼친 뒤 정규화하고 `settingsModel:"minimal"`을 붙인다. 다른 키가 하나라도 있는 legacy 모양 파일은 펼치지 않고 그대로 정규화한다(온보딩은 이를 `minimal_settings_required`로 거절한다). `load_project_config_raw`와 laya route·origin plan·cutover preflight의 raw 검사도 같은 펼침을 쓴다. **`find_project_config`는 여러 hook entrypoint가 개별 가드 없이 직접 부르는 안전 경계라 내부 탐색(`_find_project_config_unsafe`)을 try/except로 감싸 어떤 예외에도 빈 설정으로 fail-open한다** — 샌드박스/권한 차이로 경로 탐색이 죽어도 호출 훅이 non-zero exit로 죽지 않게 한다. **collection role 판정의 SSOT도 여기다**(`COLLECTION_ROLES` = raw/wiki/session/source, `INDEXED_ROLES`·`RECALL_RAW_ROLES`·`COMPILE_SOURCE_ROLES` + `collection_role`/`is_*`/`*_collections` 헬퍼). role은 **두 축의 조합**이다 — qmd에 등록되는가(=recall 대상), compile 입력이 되는가. `source`는 "compile 입력이지만 인덱싱·recall 대상 아님"이다. 도입 동기는 로드맵 8단계(raw 제거 A/B)를 가역적으로 만드는 것이었고 **8단계는 "제거 이득 0, 제거하지 않는다"로 끝났다** — 그렇다고 죽은 기능이 아니다: 대용량 자료를 "compile 입력이지만 검색 제외"로 표현하는 것은 여전히 필요하고(새로 붙이는 대형 raw 코퍼스), 기본값은 `raw`이므로 아무도 이 경로로 밀려가지 않는다. **다만 이 role이 현재 프로젝트에서 raw 제거를 정당화하지는 않는다.** **판정을 `roles.get(c) != "wiki"` 같은 여집합으로 쓰지 말 것** — 세 번째 값이 들어오는 순간 그 지점 전부가 오분류한다(source가 raw로 새어 검색·인덱싱 대상에 들어간다). **"키 없음"과 "키 있음 + 값 미지"를 구분한다** — 전자는 role 도입 전 프로젝트라 `DEFAULT_COLLECTION_ROLE`(`raw`)로 fail-open하지만, 후자는 사용자가 무언가를 의도했는데 못 읽은 것이라 `COLLECTION_ROLE_INVALID` 센티널로 **fail-closed**(어떤 role 집합에도 없어 인덱싱·recall·compile에서 전부 빠진다). 둘을 뭉쳐 raw로 보내던 동안 `"sourse"` 오타 하나가 "색인 제외"를 실제 `collection add`로 뒤집었다(실측). **센티널은 `collection_role_map`이 정규화 시에도 남긴다** — 미지 항목을 버리면 normalize 소비자에서 그 자리가 "키 없음"으로 보여 raw로 되살아나고, raw settings를 읽는 `resolve_paths`와 판정이 fail-open 방향으로 갈린다. `invalid_role_collections`가 미지 role 컬렉션을 돌려주지만 지금 이를 SessionStart 알림으로 내보내는 호출부는 없다. **compile 설정 키 3개의 처리는 서로 다르고 그 비대칭이 의도다.** (1) `compile.sourceScan.{enabled,maxCardsPerScan}`는 **읽힌다** — `enabled`는 bool만, `maxCardsPerScan`은 `MAX_SOURCE_SCAN_CARDS`(5000) 클램프다. 유료 호출이 아니라 worker I/O 예산이라 `budget` 블록에 두지 않고, `QMD_SOURCE_SCAN_MAX`는 클램프 없이 설정을 덮는 디버그 레버다. **`wiki_lifecycle`에 2차 클램프를 두지 말 것** — 유일 호출부가 정규화된 config를 받아 도달 불가한 죽은 코드가 된다(mutation 0건 검출로 확인). 비-bool `enabled`는 **기본값(True=수명 주기 유지)으로 폴백하되 조용하지 않다** — `config.invalid_compile_flags`가 그 키를 돌려준다(알림 호출부는 지금 없다). **끄는 쪽으로 읽지 말 것**: 비-bool 집합에는 켜려는 의도(`1`·`"true"`)도 있고, 수명 주기는 제품 기본 동작이다(켜진 쪽의 삭제는 `retired-wiki/` 보관본으로 복구되고 대량 삭제 가드가 폭을 막는다). `maxCardsPerScan`은 이 알림 대상이 아니다(창 폭만 기본값이 되고 순환 커서가 커버리지를 유지한다). 그리고 `sourceScan.enabled`는 **수명 주기 조치만** 끈다 — 같은 run이 세는 `ineligible`(provenance 결측 총량)은 그 스위치의 대상이 아니다. 스캐너는 `ineligibleMeasured`로 **"0"과 "안 셌다"를 구분**한다(측정된 0으로 인정하는 유일한 경로는 wiki 디렉터리 부재다). 이 구분을 없애지 말 것. (2) `compile.sourceMissingPath`는 **살리지 않는다** — 이 경로 키를 읽는 소비자가 없다(오타 하나가 과금 루프였던 클래스). `DEPRECATED_REMOVED_KEYS`에 올라 있고 알림 문구는 `config.deprecated_key_notice`가 만들지만, 지금 이 알림을 내보내는 호출부는 없다. (3) `compile.maxCardsPerSource`만 값이 **잠정 이전**된다(새 키 `budget.cardsPerSource`가 없을 때만, 같은 클램프). 즉 deprecation 알림 문구 "적어 둔 값은 무시됩니다"는 relocated 4키(`batch.maxPerRun`·`verify.maxPerRun`·`judge.maxPairsPer*`)에는 참이지만 `maxCardsPerSource`에는 **부분적으로 거짓**이다. 그 4키를 "일관성" 명목으로 함께 이전하지 말 것 — `live-settings-freeze`의 §7.2 계약을 깨고 라이브 검수 예산을 3→15·50으로 올린다(업그레이드만으로 유료 호출 증가).
- `resolve_paths.py` — collectionPaths→경로 매핑 + risky path / allowRoots traversal 검증. **출력은 세 목록이고 `entries` = `indexEntries` ⊎ `sourceEntries`다**: `entries`는 설정에 적힌 전부(compile source 경로가 쓴다), `indexEntries`는 인덱스 대상(`INDEXED_ROLES`), `sourceEntries`는 role `source`(= 인덱스에서 **빼야 할** 것). **항목 모양은 `{name, path}`를 유지한다** — role을 항목에 얹으면 downstream이 role 문자열을 다시 비교하게 되고, role 판정을 여기 한 곳에 두려는 목적과 정반대다. traversal 판정은 `contained_path(base, path, roots)` 한 곳이다(`safe_collection_path`는 base=cwd 래퍼, recall의 wiki `sources[].path`는 base=project_root로 같은 함수를 쓴다). **`from __future__ import annotations`를 지우지 말 것** — 훅은 macOS 시스템 python 3.9로도 이 모듈을 import하고 `X | None`(PEP 604)은 3.10부터다.
- `cooldown.py` — **시간 게이트(cooldown·TTL·stale lock) 판정의 SSOT.** 규칙 두 개다: (1) `expiry_active` — 만료 시각을 파일에 적는 형태는 `MAX_COOLDOWN_SECS`(24h)를 넘는 값을 식힘으로 보지 않는다(쓰기도 `expiry_value`로 같은 상한에 클램프). 상한이 없으면 오염값 `1e300` 하나가 **영구 활성**이 되어 compile(`wiki_compile_worker.cooldown_active`)·dedup 판정(`wiki_dedup_judge.cooldown_active`)이 다시 돌지 않는다 — 4단계 `load_engine_cooldowns`가 받은 처방과 같은 규칙이고 `MAX_ENGINE_COOLDOWN_SECS`는 이 상수의 별칭이다. (2) `window_elapsed` — mtime 나이를 보는 형태는 **미래 mtime**(시계 되돌림·백업 복원·파일시스템 이관)을 "창이 끝났다"로 읽는다. `now - mtime`을 그대로 쓰면 나이가 음수가 되어 창이 영원히 끝나지 않고, 방향은 지점마다 다르지만 병리는 하나다(영구 skip 또는 영구 억제). 60초 이내 시계 오차는 "방금 쓴 것"으로 존중한다(유료 호출을 한 번 더 하는 방향으로 틀리지 않게). `age_seconds`는 **진단 전용**이고 판정에 쓰지 않는다. lock 임계는 `LOCK_STALE_SECS`(600)다. **판정을 호출부에서 재구현하지 말 것** — `test/cooldown-guards.test.mjs`의 grep 가드가 `time.time() - …st_mtime`을 금지한다.
- `collection_match.py` — 편집 경로 → collectionPaths longest-prefix 컬렉션 선정. 복수 컬렉션 지원, 컬렉션 밖 편집은 빈 결과.
### 설정 해석 우선순위
`config.load_project_config`는 cwd에서 HOME 경계까지 위로 올라가며 `.memvane/settings.json`(없으면 `.auto-context/settings.json`)을 찾고, **없으면 빈 설정(`collections=[]`)을 반환**한다(`indexing:false`도 동일). cwd 폴더명을 컬렉션으로 삼는 fallback은 없다. settings가 minimal(`name`·`skipPaths`뿐)이면 indexing은 켜짐이다. 설정 파일만으로는 아무 작업도 하지 않는다 — hook·skill 작업은 setup 온보딩으로 Laya route가 선택된 프로젝트에서만 돈다.
