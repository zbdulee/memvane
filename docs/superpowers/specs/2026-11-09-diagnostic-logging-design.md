# MemVane 오류·경고 진단 로그 설계

## 목표

오류와 경고에서 설치·호스트·작업·단계·사유와 상세 스택을 연결해 원인을 추적한다. 기존 설치별 로그를 유지하고 `memvane:logs` 한 번으로 여러 설치의 기록을 시간순으로 조회한다. Claude Code, Codex, Hermes Agent와 기존 Antigravity 지원 경계를 유지한다.

## 설정과 개인정보

- 프로젝트 `settings.json`에 상세 진단 설정을 둔다. 기본값은 `false`이며 명시적인 boolean `true`에서만 켠다. 설정 파일을 읽지 못하거나 값이 잘못되면 상세 진단은 꺼진다. 기존의 비식별 이벤트 기록은 설정과 무관하게 유지한다.
- 켜진 설치는 예외 메시지 원문과 스택 프레임을 기록한다. 메시지에는 원문·경로·인증값이 포함될 수 있으므로 설치별 소유자 전용 state root에만 저장한다. 상세 기록을 외부 서비스나 모델에 자동 전송하지 않고 extractor의 wiki tail에도 넣지 않는다. 지역 변수, 프롬프트와 문서 본문은 별도로 수집하지 않는다. 예외 메시지에 포함된 내용은 원문을 유지한다.
- 상세 진단은 수집 전과 쓰기 직전에 해당 설치의 현재 설정을 확인한다. 장기 실행 worker도 매 진단에서 재확인하며, 선택 route와 연결 worktree는 검증된 main 설치의 설정을 따른다. 설정을 끈 뒤 새로 시작하는 진단은 원문을 기록하지 않는다. 마지막 설정 확인과 쓰기 사이에 이미 진행 중인 기록은 완료될 수 있으므로 설정 변경만으로 즉시 중단을 보장하지 않는다. 적용 결과에는 진행 중 작업의 경계가 있음을 알린다. 이미 기록한 로그는 지우지 않고 기존 회전 정책을 따른다.
- 운영 설치 9개에 상세 진단을 켜고 PR10 완료 후 끈다. 설정 변경은 각 프로젝트의 기존 파일·다른 설정·dirty 작업을 보존하고, 제품 명령과 승인된 운영 절차로 검증한다. 자동 종료 시각이나 새 wake는 만들지 않는다.

## 이벤트와 스택

- 기존 `events.jsonl`의 소유권·symlink 검사, 0600 파일, 비차단 best-effort 쓰기, 4 KiB 행 및 회전을 유지한다. 기존 이벤트의 의미, hook stdout·stderr·exit, 호스트 동작, 색인·큐·journal 계약은 바꾸지 않는다.
- 오류는 예외 클래스, 연결된 cause/context, 프레임의 파일·함수·줄, 원문 메시지를 기록한다. 외부 라이브러리의 파일 위치는 구분 가능하게 표시하되 필요 없는 절대 사용자 경로는 내보내지 않는다. 명시된 한도를 넘으면 일부 기록과 `truncated`를 명확히 표시한다.
- 경고에 실제 예외가 있으면 예외 스택을 기록한다. 예외가 없는 경고는 발생 지점의 호출 스택을 `origin_stack`으로 구분하고, 이미 사라진 원인 예외를 복원했다고 표현하지 않는다. 자식 프로세스가 스택을 제공하지 않으면 exit·signal 등 관측 가능한 근거와 `trace_unavailable`을 기록한다.
- 상세 기록은 요청·worker의 기존 이벤트와 128비트 불투명 진단 ID로 연결한다. 원문은 UTF-8 바이트로 직렬화해 최대 16 KiB, 최대 96개 조각으로 제한하고, 각 조각은 base64 240자 이하로 독립 행에 넣는다. 헤더에 버전·총 조각 수·원문 바이트 수·SHA-256·절단 여부, 각 조각에 ID·0부터 시작하는 순서 번호를 기록한다. 판독기는 중복·누락·인코딩·길이·digest를 확인하며 헤더나 조각이 없거나 회전·손상으로 재조립하지 못하면 불완전하다고 표시한다. 부품을 `_clean`의 256자 문자열·16개 목록·3단계 깊이 제한과 4 KiB 행 제한 안에 두고, 기존 event envelope만 남는 경로도 검증한다. 진단 실패는 원래 작업을 실패시키거나 늦추지 않는다.
- 대상은 recall 거절과 vector·selector fallback, hook 오류, sync·compile 자식 실패·지연, compile verify 오류, bundle upgrade 실패·거절, migration error와 resident 소유 증명 실패, 호스트 adapter 오류다. 일상적인 no-candidates·migration gate waiting을 오류로 바꾸지 않는다. 각 경계의 warning/error 분류는 고정 목록과 시험으로 정의한다. 각 경계에서 예외를 가진 지점과 코드만 남는 지점을 목록화한다. 기존 예외 처리에서 원인이 이미 유실되는 지점은 가능한 한 유실 전에 진단을 만든다. 외부 엔진 내부에서 수집하지 못한 스택은 없다고 표시한다.

## 통합 조회

- `memvane:logs`에서 설치별 기존 조회와 전체 설치 통합 조회를 제공한다. 사용자가 승인한 canonical project root와 기대 install ID 목록을 `$XDG_CONFIG_HOME/memvane/log-targets.json`(미설정 시 `~/.config/memvane/log-targets.json`)의 소유자 전용 registry에 기록하고 9개 대상을 각각 등록한다. registry에는 로그 메시지나 프로젝트 문서 내용을 넣지 않는다. 등록은 canonical project root를 검증하고 기존 선택 route에서 install ID·state root를 확인하며, 조회 때 현재 route를 다시 확인한다. 별칭·동일 install ID는 중복 제거하되 요청 대상별 누락과 stale·미온보딩·접근 실패를 보고한다. 목록 밖 설치는 몰래 읽지 않으며 목록 자체의 부재·손상도 보고한다. 통합 조회는 프로젝트 또는 설치 식별자·호스트·시각·작업·사유·진단 ID로 묶어 시간순으로 보여준다. 기본 출력과 일반 JSON에는 원문 메시지·스택 조각을 싣지 않고, 사용자의 명시적 상세 조회에서만 복원해 보여준다. 표시 때 ANSI escape·제어 문자를 안전하게 표현해 터미널 제어와 위조된 로그 행을 막으며, 저장된 원문은 바꾸지 않는다. 외부 모델에 운영 원문을 보내지 않는다.
- registry는 소유자 전용 디렉터리·0600 일반 파일로 no-follow·owner 검사를 통과해야 한다. 설치별 권한·no-follow 검사를 생략하지 않는다. 최대 64개 등록 대상과 통합 읽기 16 MiB 상한을 두고 설치별 바이트를 공평하게 배분한 뒤 최신 순으로 합친다. 한 설치의 로그가 나머지를 기아시키지 않는다. 읽기 실패·권한 거절·손상·회전으로 인한 누락은 설치별로 표시하고 성공으로 숨기지 않는다. 이전 버전 이벤트도 읽는다.

## 검증 기준

- 상세 모드 기본 off·명시 on·off 전환과 진행 중 writer 경계·잘못된 설정·linked worktree 및 장기 worker 반영을 임시 HOME에서 검증한다. off일 때 예외 메시지·스택 원문이 어떤 이벤트에도 남지 않는다. on일 때 원문 메시지와 파일·함수·줄, 예외 체인, 경고 발생 위치가 조회에 나온다.
- 합성 비밀과 문서 텍스트로 off/on 경계를 확인한다. 활성 모드에서도 지역 변수와 독립된 프롬프트·문서 본문은 수집하지 않으며, 상세 기록은 wiki tail이나 자동 외부 호출에 들어가지 않는다.
- registry 9개 대상의 중복·누락·stale 경로, 여러 설치·동시 writer·회전·긴 스택·조각 누락·중복·순서·digest 손상·표시 제어 문자·권한 거절·symlink·용량 상한과 이전 로그 호환을 검증한다. child stderr의 기존 4096바이트 tail만 있을 때 전체 스택으로 표시하지 않는다. 상세 기록 실패가 원래 hook 응답이나 worker 결과를 바꾸지 않는지 확인한다.
- Claude·Codex·Hermes의 공통 경로와 Python 3.13·3.9를 검증하고, 별도로 실제 9개 설치에서 설정 및 통합 조회를 확인한다. 새 버전 배포 전 SE 전환·작업 소유권과 설치별 사전조건을 확인한다. 실제 생산 오류를 일부러 만들거나 기존 로그를 삭제하지 않는다.
