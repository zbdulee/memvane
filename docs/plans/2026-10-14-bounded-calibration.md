Goal: reach guarded microbatch-1 measurement without inheriting an unconfigured smoke floor or requiring an already measured training profile.

Architecture: an explicit calibration helper, unused by normal hooks/installers, validates native OS query provenance and a RAM-relative reserve. It preserves any supplied absolute floor and process RSS cap. Calibration monitors remaining host reserve and MPS recommended-budget boundaries; it does not add loaded memory to remaining available memory again. Existing production admission, approval hash and training arithmetic remain unchanged.

Tech stack: existing Python/LocalTrainer, locked isolated Laya/PyTorch runtime, synthetic input only.

## Closeout scope and reuse restrictions

`core/context_learning/calibration.py` is a packaged code addition, not a harness-only change. It provides explicit helpers for reserve/pressure validation, both singleton groups, synchronized MPS measurements and label-free prediction cases. It has no CLI, installer, hook, automatic profile approval or learning activation connection. Existing production admission, adapter approval hash, model/device binding and training arithmetic remain intact. The machine-specific controller/observer, measured profile, source bodies, checkpoint, credentials and native logs remain outside Git.

Relative reserve2458MiB is the arithmetic result of an explicitly requested0.10 fraction on a24GiB host, not a universal absolute floor or a change to an existing user setting. `absolute_floor_mib` remains binding through max(floor,ceil(RAM*fraction)); omitting it must be an explicit calibration decision after policy provenance inspection. Existing user floors must never be silently dropped because a calibration run would otherwise defer. Remaining-reserve checking belongs to this bounded measurement path; it does not replace ordinary cold-training profile admission.

The isolated run completed one effective optimizer update containing both short synthetic pairs through microbatch1 weighted accumulation, saved a private checkpoint, and validated identical probe logits after separate-process reload. The initial singleton-only estimate underestimated later cold-load/update observations. Its receipt was retained and the reload used a larger estimate derived from those observations. Process RSS, real OS queries/pressure and MPS recommended-budget checks remained independent hard guards; underprediction was not relabeled as accurate profile validation. Unknown or adverse measurements defer without completion ACK. An initial held-out payload error was repaired by allowlisting prediction input, with no guard relaxation or second training update.

This evidence validates only the measured short synthetic input shapes on the exact MPS/model/adapter combination. The estimate remains provisional for any other workload. Do not reuse it for CPU, longer inputs, batch2, another model/adapter/device, or general operating learning; each needs fresh bounded measurement, provenance/compatibility review and normal execution authorization. Merely passing helper tests or an estimated fit does not approve those workloads. The singleton cap remains1 even if an affine estimate suggests2 fits. Relative/margin/pressure heuristics were not calibrated across PCs, and concurrent session/inbox resource changes remain live defer conditions rather than reasons to terminate sessions.
