# 프로젝트 색인 경로의 중앙 등록 관리 결정 (2026-10-17)

## 결정과 현재 구현 범위

**등록·경로 라우팅을 먼저 중앙화하고 물리 색인 DB 배치는 유지한다.** 중앙
목록은 새 권한 부여 수단이 아니라 이미 명시적으로 승인·등록된 indexing ON
범위를 찾는 읽기 모델이다. 프로젝트의 실제 검색 범위는 질의 호스트의 현재
프로젝트/worktree 경로로 따로 정한다. 운영 DB 이동·통합, 프로젝트 설정 변경,
새 외부 폴더 자동 등록은 이 결정에 포함되지 않는다.

현재 구현된 B1은 별도 목록을 만들지 않고 공유 QMD store의 기존
`approvedProjects`(승인)와 `collections.json`(이름·물리 경로 예약)을 함께 읽어,
현재 **존재하는** 외부 정규 파일 편집을 승인 소유자의 dirty queue로 연결한다.
대상 `.auto-context/settings.json`의 hash·ON·role·이벤트 정책을 다시 검사하고,
모호하거나 읽을 수 없으면 외부 라우팅을 보류한다. 삭제·이동의 이전 경로,
다른 host shell 변경 관찰, worktree별 게시 검색 view는 아직 해결하지 않았다.
기능 상태는 [같은 세션 단계 계획](2026-10-17-same-session-worktree.md)을 따른다.

## 권위와 실패 규칙

- **발견 권위:** 현재 활성 store의 승인 프로젝트 집합과 등록 collection 경로가
  소유 후보의 출처다. 새로 독립 편집할 수 있는 두 번째 목록은 만들지 않는다.
  향후 routing projection은 이 등록 상태에서 검증해 파생한다. 중앙 locator가
  권위가 되는 버전이라면 로컬 경로는 이전 입력/생성된 호환값으로만 취급하고
  양쪽을 따로 수정하지 않는다.
- **정책 권위:** 로컬 설정의 명시적 OFF·optout·role·collectionPaths와 실제
  승인 hash를 매번 대조한다. `skipPaths`는 현재 recall 결과 제외 정책이며
  인덱싱 OFF로 확대 해석하지 않는다. 외부 파일 편집은 현재 세션의 검색 scope를
  바꾸지 않는다.
- **경계:** 같은 상대 경로라도 다른 worktree는 서로 다른 root·등록 수명이다.
  중첩 root, 같은 경로의 중복 collection, symlink/alias가 소유자 판정을
  모호하게 만들면 임의 longest-prefix 선택이나 다중 broadcast를 하지 않는다.
  읽을 수 없는 설정, stale 등록, offline root는 `unavailable/deferred`이며
  ON 동의나 파일 삭제의 증거가 아니다.
- **삭제/재등록:** 이전 소유 snapshot·scope revision·incarnation과 현재
  파일 집합을 함께 써야 한다. 예전 이벤트가 새 incarnation의 큐나 view를
  갱신하지 못하도록 fence를 둔다. 삭제된 파일의 등록 metadata는 원인 분석과
  안전한 재시도를 위해 tombstone으로 보존할 수 있지만, 현재 검색 후보에서는
  제외한다. 등록 해제만으로 물리 QMD 문서·벡터를 즉시 지우지 않는다.
- **동시 쓰기:** 등록 revision/활성 포인터를 기존 lock 아래 원자적으로 게시하고
  이벤트는 조회한 revision·실제 파일 identity를 큐 쓰기 직전 재검증한다.
  B1에는 이 재검증 뒤 append까지의 경합과 게시 generation fence가 남아 있다.

## 도입 순서와 완료 증거

1. 기존 승인·등록·선택 포인터의 책임을 문서화하고, B1처럼 **기존 정보에서
   읽기만 하는** 소유자 조회를 좁게 붙인다. 현재 cwd와 외부 대상 소유자를
   구분하는 합성 회귀를 유지한다.
2. 기존 등록에서 만든 검증된 routing projection을 읽기 전용으로 구성한다.
   프로젝트 로컬/레거시 경로는 명시적 등록 없이는 자동 편입하지 않는다.
   shadow 모드에서 기존 경로와 새 경로의 소유 후보·OFF·모호성·비용을 비교한다.
3. B2의 삭제/이동 이전 owner snapshot과 incarnation fence를 도입하고,
   승인된 이벤트 경로에서만 라우터 전환을 한다. 실패 시 옛 라우터로 되돌리는
   경로를 검증한다. DB 복원은 이 롤백 절차에 들어가지 않는다.
4. worktree별 게시 index/view와 늦은 worker fence를 별도로 구현·시험한다.
   최종 설치 후보의 실제 Claude/Codex 새 세션에서 추가·수정·삭제의 긍정·부정
   검색 결과와 전환 중 상태를 확인한다.

중앙 물리 DB 통합은 별도 결정이다. 실제 QMD 지원 API/transaction, 검색·색인
비용, 동일 경로 격리, 동시 writer, 독립 복구와 롤백의 측정 증거가 생긴 뒤에만
검토한다. 현재 B1 합성 통과를 이 증거로 간주하지 않는다.
