## Summary
`memvane/vectorcache/README.md`: vector arena는 view store 옆의 파생 vector 파일이다. store는 vector 하나를 SQLite 행 하나로 두므로 한 view의 set을 읽으면 행마다 임의 page를 읽는다. arena는 같은 바이트를 append-only 파일 하나에 이어 두어 recall이 매핑해 순서대로 scan한다. 구현 파일은 `arena.py`(형식과 reader), `scan.py`(구간 묶기와 커널 scan), `writer.py`(sync owner의 writer), `types.py`(형식 번호·이름·상수·writer 상한)이다. 위치는 `<install state root>/vector-cache/`(디렉터리 0700, 파일 0600, `O_NOFOLLOW`)이다. 파생물이라 지워도 되고 1.x 영속 계약 밖이다. 파일 구성: `current.json`(활성 쌍과 정체성: 형식 번호·nonce·profile·recipe·dimension·dtype·store incarnation), `arena-<nonce>.vec`(헤더 한 페이지 + float32 × dimension 행), `arena-<nonce>.idx`(헤더 + 고정 길이 레코드 `(blob sha, first row, chunk count, set digest, vec crc, record crc)`). reader(`arena.open_arena`)는 lock을 쥐지 않고 쓰지 않는다. 디렉터리·파일이 없거나 안전하지 않거나 형식 번호·정체성·헤더가 다르면 "arena 없음"(None)이다. idx는 `record crc`가 틀린 레코드(찢어진 append)를 건너뛰고 같은 blob의 레코드는 마지막 것을 쓴다. set이 "덮였다"는 것은 마지막 유효 레코드가 store의 set digest와 chunk 수를 가리키고, 행 구간이 vec 안에 있고, `vec crc`가 매핑한 바이트와 맞는 것이다(`Arena.cover`). 그렇지 않은 set은 missing이고 호출자가 store에서 읽는다. 레코드는 있는데 맞지 않은 set은 inconsistent로도 센다. vec은 private 매핑(`ACCESS_COPY`)으로 연다. scan 커널 버퍼가 쓰기 가능한 버퍼를 요구하기 때문이며 파일에는 아무것도 쓰이지 않는다. 이 도메인은 store와 sync를 부르지 않는다. recall의 reader(store)와 sync owner의 writer가 `api`로 쓴다.
