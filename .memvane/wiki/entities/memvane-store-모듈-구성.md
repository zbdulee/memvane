## Summary
`memvane/store/README.md`: `checkout_view.py`는 caller가 보관하는 저장소·워크트리 등록 JSON과 Git checkout capture API로 경로·dev/ino, ref·HEAD·index·operation을 재검증하고 view identity를 계산한다(`docs/development-checkout-capture.md`). `blob_store.py` / `blob_schema.py` / `blob_values.py`는 schema3 view store의 내용 층(private Git-blob 형식 admission·불변 body/recipe/profile/set·metadata provenance)이며 원문 body API는 없다. `put_fingerprint`·`put_attestation` 입력은 호출자의 증거 주장이다(`docs/development-blob-candidate.md`). `blob_lease.py` / `blob_fill.py`는 private content flock과 불변 complete set 채우기로, 두 view가 공유하는 content는 한 번만 임베딩한다. callback은 SQLite transaction 밖에서 실행하며 claim은 보안 경계가 아니다. `view_fill.py` / `fill_schema.py`는 capture·manifest·recipe/profile에 묶인 durable fill cursor로, content set 뒤 별도 cursor CAS를 commit하고 완료 재호출은 쓰기·fence·provider가 없다. `view_store.py` / `view_reader.py` / `view_schema.py` / `view_values.py` / `view_fts.py` / `view_vectors.py`는 불변 세대·same-view epoch CAS·세대별 FTS·pinned lexical·exact reader이며 recall(`reader_dispatch.query_endpoint`), sync 게시(`product_sync_worker`), dedup retrieval(`wiki_compile_retrieval`)이 쓴다(`docs/development-view-candidate.md`). macOS exact semantic 검색은 `view/vector_accel.py`와 `view/view_accel_search.py`를 쓴다. `journal_reader.py`는 reader endpoint 기록·선택, view pin과 epoch floor 증명을 담당하며 `resettle_selection`이 설정·vector spec 변경 시 선택을 재봉인한다.
