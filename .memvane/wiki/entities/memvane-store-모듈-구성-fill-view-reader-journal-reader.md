## Summary
`memvane/store/README.md`: `blob_lease.py` / `blob_fill.py`는 view store의 private content flock과 불변 complete set 채우기다. schema3 sync의 vector fill이 이 경로로 content set을 재사용하므로 두 view가 공유하는 content는 한 번만 임베딩한다. 캐시는 읽기 전용이고 callback은 SQLite transaction 밖에서 실행한다. claim은 협력적 발급 객체·보유 FD 계약이며 운영 owner 권한이나 임의 동일 UID FD 조작에 대한 보안 경계가 아니다(`docs/development-blob-candidate.md`). `view_fill.py` / `fill_schema.py`는 capture·manifest·recipe/profile에 묶인 durable fill cursor와 불변 대상 metadata다. content set 뒤 별도 cursor CAS를 commit하며 완료 재호출은 쓰기·fence·provider가 없다. 계획은 본문 전체 대신 길이 metadata를 보관하며 schema3 sync owner가 view별 vector fill에 쓴다. `view_store.py` / `view_reader.py` / `view_schema.py` / `view_values.py` / `view_fts.py` / `view_vectors.py`는 capture-bound 불변 세대·same-view epoch CAS·세대별 FTS와 pinned lexical·exact reader다. 벡터 coverage는 lexical-only 또는 동일 recipe/profile의 전체 eligible member 참조이고, seal은 recipe/profile과 member blob을 봉인하며 벡터 바이트는 set digest와 행 digest로 읽을 때 검증한다(손상 바이트는 서비스하지 않음). hybrid는 같은 pin의 lexical 결과를 유지하고 semantic work/deadline만 defer한다. seal과 검색 결과는 구조적 commitment이며 운영 권한은 journal의 schema3 endpoint record가 정한다. 사용처는 recall(`reader_dispatch.query_endpoint`), sync 게시(`product_sync_worker`), write-time dedup retrieval(`wiki_compile_retrieval`)이다(`docs/development-view-candidate.md`). macOS exact semantic 검색은 `view/vector_accel.py`와 `view/view_accel_search.py`를 쓴다. `journal_reader.py`는 설치 journal의 reader endpoint 기록·선택, view pin 및 epoch floor 증명을 담당하며 sync owner의 `resettle_selection`이 설정 또는 vector spec 변경에 맞춰 선택을 재봉인한다.
