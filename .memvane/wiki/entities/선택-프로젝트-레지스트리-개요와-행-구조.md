## Summary
`docs/project-registry.md`: `memvane/registry/memvane_registry.py`는 사용자 단위 조회 색인이다. HOME state base 아래 소유자 전용 SQLite 파일 `~/.local/state/memvane/v1/auto-context/registry/projects.sqlite` 하나에 선택된 main checkout과 그 연결 git worktree의 경로를 기록한다. 레지스트리 행은 조회 후보일 뿐 권한이 아니다. 소비자는 사용 직전에 기존 선택 route 증명(route 기록·설치 journal·attestation)을 그대로 수행하며, 행만으로 recall·외부 편집 알림·쓰기·재선택을 허용하지 않는다. 레지스트리는 자기 SQLite 파일에만 쓰고 journal·route·ledger·marker·store·큐·intent를 쓰지 않는다. SQLite 자체 파일 잠금 외의 lock, wake kind, hook action은 없다. 행 필드: install ID, state root, route가 기록한 project root, 파일시스템 표기의 대상 root(`target_root`), 종류(`main`·`worktree`), 부모 install, journal `scopeId`(incarnation), 대상 root inode, 상태, 사유, 마지막 증명 결과(`proof`), 소실 관측 정보, 마지막 관측 시각, 행 버전. 상태: `active`(조회 후보), `missing_pending`(root 없음, 즉시 조회에서 빠짐), `detached`(사유 `released`·`missing`·`root_moved`), `conflict`(두 install이 같은 root 주장, 어느 쪽도 후보 아님). `missing`·`root_moved` 행은 tombstone이며 SessionStart seed·backfill 같은 암묵 등록은 tombstone을 바꾸지 않고 같은 경로의 다른 install도 넣지 않는다. 새 route 증명을 가진 명시적 활성화(`activate-index-origin`, `selected`로 끝난 `recover-index-origin`)만 tombstone을 교체한다. 진단: `python3 -B entry/run.py registry status`는 reconcile 없이 `snapshot`을 JSON으로 출력한다.
