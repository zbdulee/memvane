## Summary
worker의 per-run 상한은 `compile.batch.maxPerRun`(기본 10)이고 `batch.maxItems`(기본 5, 시작 조건)와 다르다. maxPerRun이 없으면 큐 전량을 한 프로세스가 직렬 실행한다(1,000건 = 유료 CLI 1,000회). 초과분은 requeue되어 다음 kick이 집고(`QMD_SYNC_COMPILE_MAX`와 같은 성질) `--json`의 `deferred`가 미룬 개수다. 이 값은 extractor 호출 수만 보장한다 — 한 run 유료 호출은 extractor(≤ maxPerRun) + dedup judge(≤ 쓰인 카드 수) + verify(예산)라 `compile.maxCardsPerSource`(기본 10)로 candidates 순회도 자른다(없으면 큐 5건·카드 40장에 205회). 초과분은 `skipped`/`cards_per_source_cap`로 남기고 requeue하지 않는다(이중 과금; 해법은 소스 분할). `MAX_COMPILE_PER_RUN`·`MAX_CARDS_PER_SOURCE`·`MAX_VERIFY_PER_RUN`로 클램프한다(`"100"`·`99999999` 통과 방지). 곱은 막지 않는다: 카드 수 `batch.maxPerRun × maxCardsPerSource`, 기본 최악 140회, 상한 시 2,581회. 함께 올리는 것이 사용자의 명시적 선택이고 `docs/settings.md`에 경고가 있으며, "모델 출력에서 유도된 값만 코드가 자른다" 원칙 때문이다. `memvane/wiki/compile/wiki_extract.py` 수동 경로(`wiki-compile` skill)에는 `maxCardsPerSource`가 걸리지 않는다(사용자 명시 요청).
