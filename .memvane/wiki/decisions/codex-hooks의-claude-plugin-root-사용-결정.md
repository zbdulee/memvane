## Summary
`memvane/host/README.md`: `hooks-codex.json`도 `${CLAUDE_PLUGIN_ROOT}`를 쓴다(`"${CLAUDE_PLUGIN_ROOT}/hooks/run-hook" <action> codex`). 이유는 이것이 Codex가 신뢰성 있게 주입하는 plugin-root 변수이고, 모든 codex 플러그인이 이 형태를 쓰기 때문이다. `${PLUGIN_ROOT}`만 쓰면 간헐적으로 비어 `/hooks/run-hook`으로 해석된다. 그 결과 **exit 127**이 나며, 실패 지점이 command 확장 단계라 run-hook 내부 fallback으로 막을 수 없다. `${VAR:-fallback}` 파라미터 확장과 `;`/`&&` 제어 연산자는 쓰지 않는다. 템플릿 치환에서 실패할 수 있기 때문이다. run-hook 내부는 `CLAUDE_PLUGIN_ROOT→PLUGIN_ROOT→dirname` 순서로 방어한다. CLAUDE_PLUGIN_ROOT가 비면 127이 나고 `gate`도 deny를 못 내 pending 편집 차단이 fail-open된다. 이는 수용한 트레이드오프다. same-event command hooks는 동시 실행될 수 있으므로 posttool/index/compile은 서로 순서 의존하면 안 된다. `hooks.json`은 표준 구조 `{hooks:[{type:"command",command}]}`를 따라야 한다.
