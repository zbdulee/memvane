## Summary
`publish_generation(handle, gen_id, *, expected_head)`는 원래 handle/capture/settings와 seal을 재검증하고 같은 transaction에서 `(view,incarnation,head,epoch)` CAS·상태 전환·head 증가를 수행한다. epoch는 ABA를 구분하며 다른 view 게시와 충돌하지 않는다. 정확한 replay만 허용하며 실패·busy·중간 fault는 기존 head를 보존한다. 최종 write transaction 안에서 bounded fresh Git/settings capture와 stat/settings file observations를 확인한다. 이는 검증 시점의 관측이며 filesystem/DB 원자 snapshot 보장은 아니다. Source scans/models는 writer locks 밖에 둔다. Busy는 기존2second bounded refusal/retry 코드를 사용한다.
