## Summary
`docs/continual-learning.md`: inference service는 증명 내용을 바꾸지 않고 요청마다 반복될 결과를 process 단위로 보관한다. code 파일은 stat stamp(device, inode, size, mtime, ctime)가 바뀔 때만 다시 hash하고, client wire signature는 그 file hash를 재사용한다. runtime root 안에 이미 있는 loaded module은 다시 walk하지 않는다. 모델이 이미 로드된 요청은 forward 뒤 runtime stat sweep과 module walk 없이 재검증하되 receipt, policy, attestation, pointer, artifact, adapter, code 검사는 여전히 실행한다. 모델을 로드하는 요청은 로드 뒤와 forward 뒤에 다시 sweep한다. lane을 지정한 recall 요청의 초기 검증은 같은 process에서 최대 5초 전에 시작한 같은 generation의 sweep에 기댈 수 있다(`inference_identity.IDENTITY_REUSE_SECONDS`): stat sweep과 module walk만 건너뛰며, 재사용된 검증은 5초를 연장하지 않고 실패한 검증은 이를 끝낸다. 시간 초과 후 warm 상태로 남은 첫 로드도 이를 끝낸다. warm-up과 apply는 매 검증마다 sweep한다. 따라서 runtime·model 디렉터리 변경은 최대 5초 뒤 첫 sweeping 검증에서 발견된다. `selectorIdentityReused`는 초기 검증이 재사용된 recall을 표시한다. `selectorCheckpoint`는 해당 recall을 채점한 artifact SHA-256의 앞 12 hex다.
