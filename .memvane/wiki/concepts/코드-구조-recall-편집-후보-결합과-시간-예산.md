## Summary
`docs/design-code-structure-recall.md`. hybrid 점수 가산 대신 편집 전용 후보 목록 하나를 추가한다. 순서: 편집 파일의 유일한 심볼 인용 → 양방향 import 이웃의 출처 일치 → 이웃의 명시적 문서 인용(동점은 상대 경로·카드 경로 순). 캐시는 카드 경로·SHA 쌍만 제안하고 store 유계 일괄 읽기로 같은 pin의 eligible member·신뢰·blob을 확인한 행만 채택한다. 새 고유 카드 최대 2장을 5·6위에 삽입(기존 4장 이하면 끝), 전체 15장·selector 입력 10장·최종 프롬프트 3장·편집 2장 상한 유지. RRF 첫 목록 2배 가중·1위 보너스를 단독으로 얻지 않게 하는 규칙이다. 예산 제안: 시작 경로 4개, 이웃 16개, 카드 쌍 32개, 조회·member 읽기 25ms; 실패 시 hybrid 순서 반환, 훅의 AST·Git·원문 읽기 0회 추가. `queryTimeout` 5초, 훅 18초, 편집 훅 진입 10초, 프롬프트 selector 최대 3초. recall 이벤트 사유: `hit`, `miss`, `budget`, `pin_mismatch`, `invalid`. 경로·심볼·프롬프트 원문은 새 필드에 남기지 않는다.
