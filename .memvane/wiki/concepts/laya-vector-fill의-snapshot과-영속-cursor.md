## Summary
`vector_fill_step(runtime, provider, *, max_files, max_bytes, should_yield) -> dict`는 `require_complete`로 catalog의 COMPLETE snapshot을 읽으며 없으면 `pending`/`no_snapshot`이다. `LayaSourceCatalog.manifest`는 digest만 반환하므로 fill은 같은 `scan_files` 쿼리와 eligibility 규칙의 `members(snapshot, exclusions, after=, limit=)`로 `(path, sha256, eligible)`을 path 순서로 읽는다. catalog DB의 `(snapshot seq, profile_id)`별 cursor는 `vector_fill`/`set_vector_fill`로 영속화한다. 첫 쓰기에 `CREATE TABLE IF NOT EXISTS`로 표를 만들며 `application_id`/`user_version`과 schema version은 유지한다. 이전 catalog 파일은 진행 없음으로 읽힌다. 쓰기는 다른 snapshot의 cursor 행을 제거하며 새 snapshot 또는 profile은 cursor를 다시 시작한다.
