## Summary
`docs/release.md` After the release: smoke는 working machine이 아닌 별도 기계의 test account에서 돈다. `scripts/release_smoke.py`가 operator 기계에서 SSH로 그 계정에 접속해 읽어온 것을 판정하며, 계정엔 이 저장소 checkout이 없다.
- Q1 RS-AGED(smoke account, 업데이트 직전·직후): stored device number가 live와 다른 장기 설치에서 서로 다른 카드를 노리는 prompt 5개와 edit 1개. stage medians(`pinMs`, `lexicalMs`, `stillCurrentMs`) 최대 50 ms, edit 인덱싱, sync pass가 업데이트 전보다 짧아야 함. device number가 같으면 device 항목 `NOT RUN`.
- Q2 RS-core(smoke account, 업데이트 당일): 새 synthetic project에서 RS-core 단계.
- Q3 first daily check(working machine, 당일): read-only로 기존 설치 SLO summary, 구버전 프로세스 없음, selector maintenance completed, 설치별 stored·live device numbers.
- Q4 SLO(working machine, 24 hours와 7 days): canary와 large project SLO summary에 `over` 줄 없음.
- Q5 affected paths: 변경 경로의 시나리오.
- Q6 full run(smoke account, minor 버전마다): 전체 `release-agent-qa.md` 계약과, embedding runtime 없는 계정에서 README 단계만으로 수동 단계 없이 첫 semantic recall에 도달하는 new-machine install.
실패 항목은 다음 패치의 첫 항목이다. recall을 멈추거나 데이터를 손상시킬 수 있는 결함은 당일 패치. 되돌려야 하는 릴리스는 더 높은 버전으로 되돌리며 낮은 버전으로 내리지 않는다. smoke account에 접근 불가·미준비인 날은 Q1·Q2를 `BLOCKED`로 기록한다.
