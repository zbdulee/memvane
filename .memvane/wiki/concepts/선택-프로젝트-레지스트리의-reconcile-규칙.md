## Summary
`docs/project-registry.md`의 reconcile: 한 pass는 저장된 커서 다음부터 `active`·`missing_pending` main 행을 행 수·시간 예산 안에서 확인하고 남은 예산으로 backfill한다. 한 행의 실패는 다음 행을 막지 않는다. 파일·git·journal 검사는 트랜잭션 밖에서 하고 저장은 관측 때 행 버전 compare-and-set이며 경쟁에서 진 행은 다음 pass가 본다. root가 없으면 즉시 `missing_pending`이고, 60초 이상 떨어진 독립 관측 2회와 최초 소실 뒤 24시간이 모두 지나면 `detached`(`missing`)다. 유예 24시간 안에 같은 inode와 선택 증명이 돌아오면 `active`로 복구한다. 유예 뒤 돌아온 root는 reconcile도 암묵 등록도 복구하지 않으며 명시적 재등록만 되살린다. `detached` 뒤 자동 복귀는 없다. 권한 오류 같은 관측 불가는 소실로 세지 않고, 저장된 소실 시각이 미래면 첫 관측으로 다시 센다. inode가 바뀐 root는 `detached`(`root_moved`)이며 암묵 등록도 덮어쓰지 않는다; root 이동은 경로를 자동으로 바꾸지 않는다. route 증명 실패는 해제가 증명된 경우만 `detached`(`released`), 그 밖에는 상태를 두고 `proof`에 `unproved:<사유>`를 남긴다. main은 자기 route 기록으로만 분류한다(`_select_route`). setup·`snapshot()` 경로에서 유계 `git worktree list`와 `index_host_route.select_route`의 `worktree` 판정(같은 common git dir, 자기 route 없음, 같은 settings 정체성)으로 `worktree` 행을 등록하고, 성공한 목록에서 사라진 worktree만 `detached`(`released`)다. git이 답하지 못하면 worktree 행을 바꾸지 않는다. main이 `detached`면 그 install의 worktree 행도 같은 사유로 `detached`다. worktree 행의 schema3 view ID·view 준비 상태는 아직 기록하지 않는다. backfill은 state base를 페이지 단위로 훑어 journal이 선택한 install을 route 증명 뒤 등록하며 열거 실패·중단은 완료가 아니다.
