## Summary
`agents/wiki-dedup-resolver.md`: resolver는 작업 전 프로젝트별 run-lock `~/.local/state/memvane/v1/auto-context/dedup-resolve-lock/<project_key>`를 `mkdir`로 획득한다. `<project_key>`는 `"<absolute project root>"`와 `"<config path or empty string>"`를 개행(`chr(10)`)으로 이은 문자열의 `hashlib.sha256` hexdigest다. `mkdir` 실패 시 기존 잠금 디렉터리 mtime이 60분 미만이면 다른 resolver가 활성이므로 즉시 중단하고, 60분 이상이면 stale로 보고 지운 뒤 다시 만든다. 결과와 무관하게 종료 시 잠금을 제거한다. 플러그인 루트는 `ROOT="${CLAUDE_PLUGIN_ROOT:-${PLUGIN_ROOT:-$(git rev-parse --show-toplevel)}}"`이며 모든 CLI는 `"$ROOT"`를 쓴다. 큐를 읽기 전 `python3 "$ROOT/entry/run.py" wiki-dedup-resolve --cwd <cwd> --recover-queue`로 queue lock 아래 dead-owner `dedup-needed.jsonl.claimed.*`를 회수한다. `.memvane/compile/dedup-needed.jsonl`이 비었거나 없으면 잠금을 풀고 끝낸다. CLI가 non-zero로 끝나거나 non-JSON을 출력하면 큐 변이 여부를 알 수 없으므로 전체 실행을 중단하고 잠금을 푼다; 남은 항목은 다음 `wiki-dedup` 실행으로 넘긴다. `wiki_dedup_resolve.py`, `wiki_dedup_scan.py`, 큐 파일은 직접 편집하지 않으며 memvane-db 검색 큐에도 직접 쓰지 않는다. 완료 시 처리 쌍, 삭제 파일명, 병합 카드, skip 쌍과 사유, 큐가 비었는지를 보고한다.
