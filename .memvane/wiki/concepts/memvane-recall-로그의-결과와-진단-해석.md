## Summary
`skills/logs/SKILL.md`: recall 로그에서 `reason`은 최종 결과(`selected`, `no_results_after_filter`, `no_candidates`, 또는 refusal code)이고 `notes`는 도중의 진단 목록이다. `laya_vector_*` = query vector 없음, `laya_selector_*` = local selection이 hybrid rank로 fallback, `laya_recall_proof_retry`. `degraded`는 `worktree` 또는 `reader_endpoint` read를 식별한다. semantic search가 완료되면 `injectedCosine`은 주입된 각 카드의 cosine을 주입 순서로 나열하며(semantic list에 없던 카드는 `null`), `semanticOnlyInjected`는 lexical lists에 없던 주입 카드 수다. 주입되지 않은 candidate는 row에 path나 score를 남기지 않는다. 새 index format으로 제공된 recall은 `store_format: schema3`를 가진다. 이때 `reason` `view_preparing`은 이 checkout의 view에 아직 published generation이 없음(linked worktree의 첫 사용 또는 방금 전환한 branch), `checkout_changed`는 read 중 checkout이 계속 움직였음을 뜻한다. 둘 다 다음 sync가 view를 publish할 때까지 context를 주지 않는다. `reader_settings_resealing`은 프로젝트 recall settings(`skipPaths` 등)가 바뀌어 index reader가 이 recall이 요청한 다음 sync에서 re-seal된다는 뜻이며 그때까지 context를 주지 않는다.
