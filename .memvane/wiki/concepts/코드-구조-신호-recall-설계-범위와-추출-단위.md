## Summary
`docs/design-code-structure-recall.md`(1.1 이후 설계안, 수치는 모두 제안값이며 실측 없음). 1차 범위: Python 파일 편집 시 직접 import하는 쪽과 그 파일을 import하는 쪽(양방향 한 단계)의 검증된 위키 카드를 찾는다. Python 정의 이름과 Markdown의 명시적 코드 참조도 쓴다. 예: `billing/rate.py`의 `quote` 편집 → 이를 import하는 `checkout/total.py`를 근거로 한 카드. 프롬프트의 정확한 이름은 2차, 카드 최신성(심볼 해시로 재검수 우선순위)은 별도 실험. 전체 호출 그래프·자연어 관계 추론·코드 검색 결과 직접 주입은 범위 밖. SQLite store 하나와 Python 3.9 표준 라이브러리만 쓴다. Python 정의는 `ast.parse`로 읽어 상대 경로·전체 SHA-256·한정 이름·종류·시작/끝 줄·범위 SHA-256을 남긴다(데코레이터 줄부터 해시, 조건부·중복 정의는 단일 심볼로 확정 안 함). import는 `import pkg.mod as m`, `from .mod import f as g`를 풀고 목적지가 유일할 때만 정·역방향에 넣는다(외부 패키지·별표·모호한 루트 제외). JS·MJS·TS는 2차, 제한 토큰 스캐너. 소스 줄·본문·주석·docstring·AST 직렬화는 저장하지 않는다. 구조 추출기는 raw 확장자 목록과 별개 소비자다.
