## Summary
`docs/dev/contexts/working-rules.md` 기준 새 벽시계 단정을 쓰기 전에 그 회귀를 개수·상태로 표현할 수 있는지 먼저 확인한다. 예를 들어 프로브·질의 개수, 하네스 timeout의 `res.signal`, 완료 마커 존재 여부로 표현할 수 있다. `spawnSync`는 timeout 시 `status: null`·`signal: 'SIGTERM'`을 주므로 `notEqual(status, 0)`이 버그가 있어도 공허하게 통과한 사례가 있었다. 폴링 대기에는 `execFileSync('sleep', …)`를 쓰지 않는다. 대신 `waitUntil`(동기)이나 `waitUntilAsync`(자식 프로세스 테스트용)를 쓴다. 동기 sleep은 SIGCHLD 수확을 막아 좀비를 살아 있는 것으로 읽게 만든다. 테스트는 제품 데이터를 건드리면 안 된다. 이벤트 로그는 검증된 install state root(0700, symlink 없는 경로)에만 쓰이므로, 테스트는 임시 HOME과 `realpath`로 푼 fixture state root를 쓴다. `execFileSync`에는 반드시 `encoding:'utf8'`을 준다. 생략하면 Buffer가 반환되어 `.trim()` 에러가 난다. 병렬 실행 시 `__pycache__`가 spurious 실패를 유발할 수 있어 `.gitignore` 처리돼 있다. node 테스트 프로세스 안에 http 서버를 띄우지 않는다. `execFileSync`가 event loop를 막기 때문이며, stub 서버는 Python driver(스레드 서버 + subprocess)에서 띄운다.
