## Summary
`docs/templates/release-agent-qa-run.md`의 Preflight (spec section 3, before functional QA)는 functional QA 전에 Claude Code·Codex별로 기록한다. 항목 결과는 `ready`, `not ready`, `NOT RUN`뿐이며 수행하지 않은 check는 `NOT RUN`으로 남는다. `ready`가 아니면 Class를 environment unready / approval pending / host unsupported / product defect 중 하나로 적고 retest rule을 기록한다. 항목: PF-ID(exact candidate commit, version, installed byte identity), PF-FOLDER(project folder access, exact folder approved where prompted), PF-TRUST(installed hook map and reviewed exact commands; per-hook UI approval where required), PF-FRESH(fresh session after install/trust/reload, SessionStart trace; new prompt log path), PF-HOST(surface CLI/app, sandbox mode/env, required event support; delivery checked in scenarios), PF-RUNTIME(OS build/arch, hook `python3`, Node, Git, hash tools), PF-NET(online / offline policy / sandbox-denied / DNS failure / remote outage). **Preflight result**는 모든 항목이 `ready`일 때만 `READY`다. Exact trust scope는 host당 한 행이며 wildcard나 "trust all"은 금지한다. 열: Host, Surface, Approved folder (exact, or no prompt), Reviewed hook commands (full list, from installed hook map), Host approval route (official UI if required) / time, Hook map SHA-256 matches candidate?
