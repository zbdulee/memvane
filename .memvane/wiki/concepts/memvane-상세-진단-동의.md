## Summary
`docs/superpowers/specs/2026-11-09-diagnostic-logging-design.md`의 설계: 상세 진단 설정은 프로젝트 `settings.json`에 둔다. 기본값은 `false`이며 명시적인 boolean `true`일 때만 켜진다. 설정 파일을 읽지 못하거나 값이 잘못되면 꺼진 것으로 처리한다. 기존 비식별 이벤트 기록은 이 설정과 관계없이 유지된다. 켜진 설치는 예외 메시지 원문과 스택 프레임을 설치별 소유자 전용 state root에만 저장한다. 이 기록은 외부 서비스나 모델에 자동 전송하지 않고 extractor의 wiki tail에도 넣지 않는다. 지역 변수와 프롬프트·문서 본문은 별도로 수집하지 않는다. 설정은 수집 전과 쓰기 직전에 다시 확인한다. 장기 실행 worker도 진단마다 재확인한다. 선택 route와 연결 worktree는 검증된 main 설치의 설정을 따른다. 설정을 끈 뒤 새로 시작하는 진단은 원문을 기록하지 않지만, 이미 진행 중인 기록은 완료될 수 있다. 따라서 설정 변경만으로 즉시 중단되지는 않는다. 이미 기록된 로그는 지우지 않고 기존 회전 정책을 따른다. 이벤트 기록은 기존 `events.jsonl`의 0600 파일, symlink 검사, best-effort 쓰기, 4 KiB 행 제한을 유지한다. hook stdout·stderr·exit와 색인·큐·journal 계약은 바꾸지 않는다. 진단에 실패해도 원래 작업을 실패시키거나 늦추지 않는다. 자식 프로세스가 스택을 제공하지 않으면 exit·signal과 `trace_unavailable`을 기록한다. 운영 설치 9개에 상세 진단을 켜고 PR10 완료 후 끄되, 자동 종료 시각이나 새 wake는 만들지 않는다. 검증은 임시 HOME, 합성 비밀, Claude·Codex·Hermes 공통 경로, Python 3.13·3.9 환경에서 수행한다.
