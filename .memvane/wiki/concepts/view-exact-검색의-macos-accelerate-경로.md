## Summary
`memvane/store/README.md`: macOS exact semantic 검색은 `view/vector_accel.py`의 지연 로드 Accelerate 커널과 `view/view_accel_search.py`의 대량 읽기를 쓴다. pin의 member만 읽고 모든 행의 모양·유한성·norm, 상위 60장의 set·행 digest를 검증하며 최종 점수는 기존 Python 함수로 계산한다. 게시 시점에는 전체 set을 검증한다. `MEMVANE_VECTOR_ACCEL=off`나 커널 부재 시 모든 set을 검증하는 Python 경로와 기존 float 연산량 상한을 쓴다. native lane의 `search_exact`는 store 파일 옆 `vector-cache/`의 vector arena(`memvane/vectorcache`)를 먼저 읽고, arena가 덮은 set은 매핑한 행에서, 덮지 못한 set만 store에서 대량으로 읽어 카드별 최고 점수로 합친다. store 읽기 상한(`MAX_ROWS` 40,000행·`MAX_BYTES` 128MiB)은 덮지 못한 행에만 걸리며 넘으면 `vector_cache_building`(recall의 `deferred_cache_building`, lexical 유지)이다. arena 실패(파일 없음·정체성 불일치·digest나 crc 불일치 레코드·유효하지 않은 행·reader 예외)는 그 set 또는 전체를 store 읽기로 돌릴 뿐 검색을 실패시키지 않는다. `embedding_set_invalid`는 store에서 읽은 바이트에서만 난다. 상위 후보는 store에서 다시 읽어 채점하고 arena 점수와 1e-4 넘게 다르면 store 점수를 쓴다. 보고 필드: `vectorSource`(`arena`·`store`·`python`), `vectorMissing`(arena가 답했을 때 store에서 읽은 행 수), `vectorCache`(`ok`·`building`·`absent`·`disabled`·`inconsistent`). `MEMVANE_VECTOR_ACCEL=store`는 arena를 열지 않고(`disabled`) 상한 밖은 `vector_work_exceeded`다. coverage는 blob 256개씩 묶어 읽는다(`view_accel_search.heads`). arena writer는 sync owner(`memvane/sync/vector_cache.py`)이며 store는 살아 있는 set 목록(`arena_sets`)과 검증한 set 바이트(`arena_set`)를 준다.
