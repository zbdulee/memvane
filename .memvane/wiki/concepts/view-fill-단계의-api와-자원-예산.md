## Summary
`ViewStore.fill_view`의 기본값은 `max_files=8`, `max_bytes=2000000`, `deadline_seconds=30`이며 명시 범위는 max_files1..64와 max_bytes1..64MiB다. body가 호출 byte budget보다 크면 cursor advance 없이 deferred다. 자동 예외 없이 호출자가 기존 MAX_BODY4MiB까지 budget을 늘린다. 호출당 첫 candidate DB mutation 전에 `write_fence`를 한 번 실행하며 job metadata/content writes/cursor updates가 latch를 공유한다. 완료 작업 반복과 complete content cache hit는 DB mutations/fences/providers가 모두 0이다. pending cursor repair는 provider0·fence1이다. set과 cursor commit은 별개이며 crash-wide exactly-once 보장은 없다. callback·flock wait 동안 SQLite transaction을 유지하지 않는다.
