## Summary
`docs/development-resource-safety.md`의 가용 메모리 제안 35%는 보수적이며 미보정이다. 24 GiB에서는 약 8.4 GiB이고 macOS `memory_pressure -Q`가 보는 headroom은 단순 free pages와 다르다. admission과 실행 지속 조건은 critical OS memory pressure가 없고, admission 대비 swap 증가가 물리 RAM의 10% 이하(24 GiB Mac에서 모델 로딩만으로 swap이 약 0.5–1 GiB 증가)이며, CPU당 load가 0.75 이하다.
관측한 child tree 전체에서 RSS는 물리 RAM의 15%, CPU는 전체 capacity의 25%, 프로세스는 32개가 한도다. CPU는 `ps %cpu` 수명 평균 추정치이며 순간 hard quota가 아니다. thread pool 환경 기본값은 1 thread다. RSS 합계는 shared pages를 중복 계산할 수 있어 거절이 보수적일 수 있으며, 단일 프로세스 한도로 부모·자손 합계를 대체하지 않는다.
샘플링 기본값은 5초마다(허용 2–10초), job 예산은 900초(최대 1800)다. sleep과 각 OS probe는 남은 wall-time 예산으로 제한되고 cleanup은 별도 10초 probe 예산을 쓴다. 잘못되거나 읽을 수 없는 OS/process 관측은 admission을 거절하거나 소유 작업을 중지한다. Sandbox EPERM은 죽은 프로세스나 가드 완화 허가로 취급하지 않는다. Linux는 MemAvailable과 memory PSI를 쓰며 미지원 monitor는 실행을 거절한다.
