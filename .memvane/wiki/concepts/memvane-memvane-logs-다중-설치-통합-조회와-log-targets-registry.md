## Summary
`docs/superpowers/specs/2026-11-09-diagnostic-logging-design.md`의 설계: `memvane:logs`는 설치별 기존 조회와 전체 설치 통합 조회를 함께 제공한다. 사용자가 승인한 canonical project root와 기대 install ID 목록을 `$XDG_CONFIG_HOME/memvane/log-targets.json`(미설정 시 `~/.config/memvane/log-targets.json`)의 소유자 전용 registry에 기록하며, 운영 대상 9개를 각각 등록한다. registry에는 로그 메시지나 프로젝트 문서 내용을 넣지 않는다. 등록 시 canonical project root를 검증하고 기존 선택 route에서 install ID·state root를 확인하며, 조회할 때 현재 route를 다시 확인한다. 별칭과 동일 install ID는 중복 제거하되, 요청 대상별 누락과 stale·미온보딩·접근 실패를 보고한다. 목록 밖 설치는 읽지 않으며 목록 자체의 부재·손상도 보고한다. registry는 소유자 전용 디렉터리의 0600 일반 파일이어야 하고 no-follow·owner 검사를 통과해야 한다. 설치별 권한·no-follow 검사도 생략하지 않는다. 등록 대상은 최대 64개, 통합 읽기는 16 MiB 상한이다. 설치별 바이트를 공평하게 배분한 뒤 최신 순으로 합쳐 한 설치의 로그가 나머지를 기아시키지 않게 한다. 읽기 실패·권한 거절·손상·회전으로 인한 누락은 설치별로 표시하며 성공으로 숨기지 않는다. 이전 버전 이벤트도 읽는다. 통합 출력은 프로젝트 또는 설치 식별자·호스트·시각·작업·사유·진단 ID로 묶어 시간순으로 보여준다. 기본 출력과 일반 JSON에는 원문 메시지·스택 조각을 싣지 않고, 사용자가 명시적으로 상세 조회를 요청할 때만 복원한다. 표시할 때는 ANSI escape·제어 문자를 안전하게 표현하고, 저장된 원문은 바꾸지 않는다. 운영 원문은 외부 모델에 보내지 않는다.
