## Summary
`docs/release.md` RS-core: 제품은 hooks와 자연어 요청으로만 진행한다. operator는 단계를 진행시키려고 product entry point나 skill script를 실행하지 않으며, 판정용 읽기(event rows, hashes, process lists)만 허용된다. 세션은 smoke account의 terminal multiplexer 안 interactive host CLI로 login shell에서 시작한다. headless는 쓰지 않는다(hook이 조용히 끝나고 실제 사용 방식이 아님).
operator는 프로젝트 디렉터리에서 host별 `screen` 세션 `smoke-claude`, `smoke-codex`를 UTF-8 mode, detached, login shell 명령으로 시작한다. tool은 세션 이름으로 window 0을 지정해 prompt를 paste하고, window가 바뀐 뒤 멈출 때까지 기다리며 짧은 prompt는 자신의 token이 보이는지 확인한 뒤 Enter를 따로 보낸다. paste를 관측하고, hook이 보는 prompt는 prompt hash의 event row까지 관측해야 성공이며 아니면 non-zero exit, 항목 `BLOCKED`. prompt는 한 줄이고 run token을 담아 이전 run row와 매칭되지 않는다. 전송 전 input line이 보이고 permission·trust 화면이 없는지 확인한다.
단계: prepare(sandbox·test 변수 없음 확인, verified card가 붙은 raw 문서로 synthetic project 생성; forbidden variable은 run 무효) → update(README대로 업데이트·프로젝트 활성화, Codex hook trust는 사용자가 승인; RS-UPDATE) → identity(RS-ID) → model address(pinned 주소 fetch, size·sha256; RS-MODELURL) → sessions(SessionStart row; RS-HOSTENV, 없으면 해당 host 이후 `BLOCKED`) → onboarding(RS-ONBOARD) → new sessions 재시작(RS-HOSTENV) → recall(vector generation publish 후 짧은 prompt와 12,000 character prompt; RS-RECALL) → repeat(RS-DEDUP) → edit(edit tool로 고정 문단 추가; RS-EDIT) → sync(문서 3개·카드만 write/remove/commit, 최신 event row 시각 기록, host 세션에 index refresh 요청, 그 이후 indexed sync pass와 publish 대기, 없으면 non-zero; 중단 시 같은 record directory로 재실행; RS-SYNC) → verdict(gate files 작성).
