## Summary
`docs/project-registry.md`의 레지스트리 쓰기 지점: 활성화 성공 뒤 `setup_entry`가 `after_setup`으로 route를 다시 증명해 main 행을 idempotent upsert하고 유계 reconcile을 한 번 돈다. `restore-index-origin` 성공 후 재관측(route가 그 install을 가리키지 않고 journal이 `selected`가 아님)이 성립할 때만 그 install 행을 `detached`(`released`)로 바꾸며, `blocked`·`recovery_required`·`rejected`나 재관측 실패는 행을 바꾸지 않고 해제 명령은 행을 새로 넣지 않는다. 선택된 main checkout의 SessionStart hook이 자기 행을 seed하고 유계 reconcile한다(`HOOK_ROWS` 4행, `HOOK_BACKFILL_PAGE` 8항목, `HOOK_SECONDS` 0.5초). 이 reconcile은 git을 실행하지 않으며 연결 worktree 행 등록·해제는 setup 성공 뒤와 `snapshot()` 경로만 한다. `snapshot()`(대시보드 조회)은 기본 예산(32행, backfill 32항목, 2초)으로 reconcile한 뒤 읽는다. 어느 쓰기도 명령 결과·exit code·hook 출력을 바꾸지 않고, 쓰기 실패는 다음 reconcile이 복구한다. state root가 HOME state base 바로 아래가 아닌 설치(fixture state root 등)는 기록하지 않는다. resident service는 reconcile하지 않으며, 승인되면 `memvane_registry.reconcile()` 1줄 호출로 붙인다. SessionStart reconcile 예산은 `HOOK_SECONDS`와 `hook_budget.remaining()`에서 1초를 뺀 값 중 작은 쪽이고 0 이하면 하지 않는다. `HookDeadlineExceeded`와 레지스트리 부재·손상·busy·예외는 SessionStart 응답을 바꾸지 않는다(fail-open).
