## Summary
`memvane/store/README.md`: 다른 도메인은 `memvane.store.api`의 함수만 쓴다. `open_store`가 돌려준 열린 view store의 공개 메서드(`capture_view`, `head`, `pin_view`, `release`, `prepare_generation`, `publish_generation`, `ingest_attested_card`, `fill_view`, `fill_status`, `search_exact`, `vectors`, `close` 등)는 그대로 부른다. store의 `_` 멤버나 store 테이블(`store_meta`, `worktrees`, `s_*`, `embedding_sets`, `chunk_sets` 등)이 필요한 읽기·쓰기는 api 함수로 한다. `application/store_ops.py`: 수명과 정체성(`observe_binding`: 열거나 만들고 워크트리 하나를 관측한 뒤 닫는다, `open_store`, `store_identity`), `read_header`(store 파일을 직접 열어 한 query_only 스냅샷으로 `store_meta`와 워크트리 행을 읽고 `types.STORE_HEADER_KEYS` dict나 None 반환, `recover=True`는 hot journal rollback, 파일 정체 대조는 호출자가 앞뒤로 한다), pinned 읽기(`pinned_vector`, `vector_profile`, `eligible_members`, `worktree_wiki_root`), `skipPaths` 판정(`admitted_paths`). `application/view_sync.py`: sync owner의 view pass용 읽기·쓰기(`read_view_baseline`, `head_same`, `compile_evidence_stored`, `linked_worktree_id`, `embedding_sets_missing`, `embedding_coverage`, `fill_plan`, `put_source_fingerprints`); 무엇을 넣고 언제 게시할지와 journal fence는 sync가 정한다. 값 함수: checkout capture(`capture_view`, `capture_matches`), provider vector spec(`provider_spec`, `register_provider_spec`, `qmd_first_pass`, `query_values`, `profile`), blob 값(`regular`, `digest`, `markdown_title`, `provenance_digests`, `relative`). 예외: route(층 2)는 store(층 3)보다 아래 층이라 `index_host_route._store_identity`의 `store_meta` 읽기는 api를 쓰지 않는다. 따라서 `store_meta`의 `singleton`(값 1인 한 행)·`incarnation`·`scope_id` 열 이름과 뜻은 route와의 계약이며, store가 바꾸려면 route도 같이 바꾼다.
