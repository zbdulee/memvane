## Summary
호출자는 binding을 질의마다 명시하며 query는 catalog나 최신 snapshot을 열지 않는다. `CandidateQuery`는 open 시 binding type·view-seal scope/generation/manifest·`index.incarnation()`·canonical no-follow roots의 `(dev, ino)`를 검사한다. root 누락은 `collection root unavailable`, 교체는 `collection root replaced`다. exclusions는 한 번 로드한다. `finish()`는 `rev_epoch` 포함 seal·incarnation·live roots를 재검사한다. 중간 exclusion 추가·root 교체·DB 재생성은 `index_stale`로 전체 실패한다. 잘못된 scope/generation/collection·malformed row·`fetch` 오류도 `candidates_unverified`가 아닌 `index_stale`이며 session을 poison한다. 이후 `finish()`는 `candidate query already failed`로 이전 phase 결과 제공도 막는다.
