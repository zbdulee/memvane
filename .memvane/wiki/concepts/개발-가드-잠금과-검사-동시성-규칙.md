## Summary
`docs/dev/contexts/working-rules.md` 기준 테스트·백업·해시 같은 무거운 개발 작업은 사용자 전역 `scripts/development_guard.py` 잠금을 거친다. 일반 focused 검사(`npm run test:focused`, `--kind test`)는 worktree/에이전트를 합쳐 최대 3개까지 동시에 돌고 파일 병렬도는 1, timeout은 900초다. 전체 검사(`npm test`, `--exclusive`)·백업·해시·실제 모델 검사·리뷰·calibration은 단독으로 돌며, 이들이 도는 동안 일반 검사도 시작하지 않는다. 자리가 없으면 exit 75로 거절되므로 기다렸다 다시 시도한다. `npm test`는 네 부분 `test:part1~4`(소요 기록으로 균등 배분)를 각 1,800초로 돌린다. 파일 병렬 3을 요청하며, 시작 표본의 메모리 압력이 `normal`이면 3, 아니면 1로 돌린다(거절하지 않음). 프로세스 수는 내부 자식 프로세스까지 합산한다. `test:guard-unit`(작은 합성 보호 장치 단위 검사)만 bootstrap 예외다. 단독 명령은 `npm run dev:guard -- --kind backup -- <명령>`, `--kind hash`, `--kind model-test -- node --test <실제 모델 시험>`으로 실행한다. `--kind test`(CI 포함)·`--kind review`·`--kind hash`는 학습용 OS 압력·CPU/RSS·headroom·swap·load 제한을 적용하지 않는다. 다만 전역 단독 실행, 파일 병렬도, 유한 timeout, 프로세스 수와 소유 식별·정리는 유지한다. `--kind model-test`와 `--kind backup`, 명시적 calibration envelope는 자원 제한을 유지한다. 로컬 `.development-hold.json`이 true인 동안에는 일반 검사·백업/해시·모델 작업·운영 활성화를 재개하지 않으며, 보류를 해제하는 사용자 지시가 있어야 재개한다. 샌드박스의 관측 거부는 명시적으로 보고하고 가드를 끄지 않는다. 참고 문서는 `docs/runtime-resource-coordination.md`, `docs/development-resource-safety.md`다.
